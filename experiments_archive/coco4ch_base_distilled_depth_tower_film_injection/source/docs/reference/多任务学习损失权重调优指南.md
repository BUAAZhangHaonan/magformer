# 多任务学习损失权重调优指南

## 第一步：归一化与观测

**核心原则：先归一化，然后观测，再谈别的。**

训练开始前的头几个 batch，记录每个子 loss 的初始量级，训练时把每个 loss 除以这个初始值。这样所有 loss 起步都在 1 附近，后面的权重才是公平的权重。

然后打开 tensorboard，盯住两样东西：
- 每个子 loss 的下降曲线
- 每一对任务在共享层上的梯度余弦相似度

> 很多人调一周调不出来，根本原因是他们从来没看过这两样东西。**没有观测就没有调优。**

---

## 第二步：Uncertainty Weighting（不确定性加权）

**几行代码即可实现，替代手动调权重。**

```python
import torch
import torch.nn as nn

class MultiTaskLoss(nn.Module):
    def __init__(self, num_tasks):
        super().__init__()
        self.log_vars = nn.Parameter(torch.zeros(num_tasks))

    def forward(self, losses):
        total = 0
        for i, loss in enumerate(losses):
            precision = torch.exp(-self.log_vars[i])
            total += precision * loss + self.log_vars[i]
        return total
```

**使用方法：** 把 `log_vars` 一起丢进优化器。原来那一行 `a * l1 + b * l2 + c * l3`，直接换成 `MultiTaskLoss()([l1, l2, l3])`。不用再手调权重了。

> 这一步做完，大多数人就能追平甚至超过之前网格搜索一周的结果。不是这个方法有多神，是手动调权重的人绝大多数都没把量级归一化做干净。**UW 是你的基线，不是你的终点。**

## 第三步：梯度冲突处理（梯度手术）

**触发条件：** 如果观察到任务之间持续的梯度冲突（余弦长期小于 0），而且 UW 加归一化之后仍然出现加一个 loss 主任务就掉的情况，就要上梯度层面的方法了。

### 方法选择

**模型不大、任务数不多，三选一：**

| 方法 | 特点 | 适用场景 |
|------|------|----------|
| **PCGrad** | 最早的、最容易理解的基线 | 入门首选 |
| **CAGrad** | 稳定性和理论上都比 PCGrad 好一档 | 中等规模任务的首选 |
| **Nash-MTL** | 对 loss 尺度完全不变，鲁棒性最好 | loss 量级差异极端或随训练进程变化很大时（如 RLHF 里的奖励 loss 和 KL loss） |

**大模型、任务数多、显存紧张：**
- **FAMO**：不需要对每个任务单独反传，在保留动态平衡效果的同时计算开销和单任务几乎一致。这是 2023 年以后新做的大模型多任务训练的默认选项。

> **不需要自己从头实现。** [LibMTL](https://github.com/median-research-group/LibMTL) 这个库把上面所有方法都封装好了，接口统一，换方法只需要改一行配置。这是目前 PyTorch 生态里最成熟的多任务训练工具，把你从造轮子里解放出来。

---

## 第四步：架构层面解耦

**触发条件：** 任务数膨胀到十几个甚至几十个，梯度层面的手术本身就变得不划算了。

这时候应该跳出优化方法这一层，考虑结构层面的解耦：
- **Mixture-of-Experts (MoE)**：让不同任务走不同专家，共享参数变少，冲突自然减少
- **稀疏训练**：让不同任务只更新模型的不同子集，从源头上避免竞争

> 这两个方向是 2024 年之后大模型多任务研究的主流。

**简单讲就是：任务少的时候在梯度上修，任务多的时候在结构上分。**

---

## 核心洞察：从手动调参到自动优化

### 问题的本质

你以为的答案是，有某种算法能帮你算出最优的 a、b、c。

**真正的答案是，当你问出这个问题的时候，你就已经困在一个错误的框架里了。** 系统的方法不是怎么更好地选 a、b、c，而是让 a、b、c 变得不再重要。

- 用 **Uncertainty Weighting** 让权重变成可学习参数
- 用 **CAGrad** 或 **Nash-MTL** 让方向冲突被直接处理掉
- 用 **FAMO** 把这一切压缩到几乎零额外开销
- 用 **MoE** 从结构上把冲突消解掉

> **手工调权重的尽头，是意识到权重根本不该手工调。**

---

## 多任务优化的几何直觉

多任务优化真正的痛点从来不是调参慢，而是它挑战了我们对优化这件事的基本直觉。

**单任务时：** 优化这件事有一个很干净的几何图像——一个曲面，一个最低点，你沿着梯度往下走。

**多任务时：** 你面对的是多个曲面叠在一起，不再有唯一的最低点，你有的是一整条**帕累托前沿**——一族彼此之间无法直接比较的、都算最优的解。你的 a、b、c 只是在这条前沿上预先钉死了一个点让你去逼近。

而前面讲的那几种动态方法（UW、GradNorm、PCGrad、CAGrad、Nash-MTL、FAMO），它们都在做同一件事：**让模型自己在这条前沿上游走，去找一个对当前训练阶段最合适的点。**

从 2018 到 2023 的每一篇工作，都是在回答同一个问题的不同侧面：**如何把这条前沿走得更聪明、更稳、更省。**

> 这就是为什么那一行看起来无辜的 `a * l1 + b * l2 + c * l3` 会让那么多人困惑、调参、怀疑人生。它背后藏着一个高维向量场的几何问题，而你手里只有三个标量旋钮。这个问题严肃到整个领域花了七年时间、几十篇顶会论文才把它从加法思维推到博弈论、再推到帕累托几何、再推到结构解耦。**你在工位上调一周调不出来，不丢人。**

---

## 掌握后的工作流

某一天，当你真的把多任务这套东西玩明白了：

你接到一个新任务，要同时优化四件事。你不会再打开一个 excel 去列网格搜索的方案。你会先写几行代码把 loss 归一化，打开 tensorboard 监控梯度余弦，套上 UW 跑一次基线。看一眼 loss 曲线，看一眼梯度余弦的分布，你立刻就能判断这几个任务之间是**协作的还是对抗的**，瓶颈在**量级上还是方向上**，下一步该上 **CAGrad** 还是 **FAMO**，还是干脆加一层 **MoE** 做结构上的解耦。

> **你脑子里跑的不再是 a 调大一点会怎么样，而是一组向量在高维参数空间里此消彼长的几何画面。**
