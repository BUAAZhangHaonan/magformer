## 阶段 1：确定性 BUG 修复（本会话，顺序执行，每项一个 commit）

### P1 — AIM `sel[:16]` 数量帽（matcher.py:219/287）
- **证据**：val 50.9% (4849/9531) COCO-small GT 出帽退回噪声均匀列；train 49%（scale=1）；4096px² 资格线每图均值 12.7、p90=41。AIM 设计意图=覆盖全部小 GT。
- **修复**：`_aim_small_gt_costs` 保留全局 bbox/R 计算（同一 R 保证离散化一致），把 point_sample+einsum 段按 `sel` 分块（chunk=16）累积 (Q,n) 代价列，去掉数量帽；`_grounded_small_gt_costs` 的帽直接移除（该路径本就是逐 GT Python 循环，无显存风险）。分块不改变数值结果（同 R 同网格），仅限峰值显存。
- **单测**（新增 `tests/test_aim_full_coverage.py`）：25 个小 GT 的合成场景，(a) kept 数==25（旧代码 16）；(b) 分块结果与逐 GT 参考实现 allclose；(c) 确定性两次调用一致；(d) 复用 1px/贴边/空 GT 用例。CPU 可跑（point_sample 支持 CPU），封存后 GPU 复跑计时。
- **验证门**：单测全绿 + 封存后用 GPU 重跑 R3 的覆盖统计（`reviews_20260920/r3_recall/aim_train_coverage.py` 改为读修复后代码）→ 覆盖率 100%。

### P2 — copy-paste 深度通道（dataset.py `_InstanceBank` + transforms.py `CopyPasteTransform`）
- **证据**：bank 条目无 crop_depth 字段；贴入段（transforms.py:1103-1109）只写 `image`，`result["depth"]` 零操作；零是全 RGB-D 路径的规范无效深度值（transforms.py:847）。
- **修复**：
  1. `deposit()` 增加可选 `depth` 参数，同窗口裁剪存入 `crop_depth`（无深度时 None）；调用点（dataset.py:647）传 `result.get("depth")`。
  2. bank `state_dict` 版本 1→2：新条目含 crop_depth 张量；`load_state_dict` 兼容 v1（缺字段→None）与 v2。
  3. `CopyPasteTransform.__call__`：当 result 有 depth 时，**只接受带 crop_depth 的 bank 条目**（防 RGB-深度-掩码三方矛盾——这正是原 bug 的危害）；深度 crop 走与 RGB 相同的 scale jitter（INTER_LINEAR）与贴入窗口；写入规则 `depth[y1:y2,x1:x2] = where(paste_mask & (src_depth>0), src_depth, dst_depth)`（源无效像素保留目标深度）。
  4. 新增 config 键 `copy_paste.prefill_images`（默认 0=关）：dataset 构造时从训练集前 K 张图预填 bank，解决 num_workers fork 副本冷启动为空的问题；**小目标场景参数值**（bank_capacity≥2000、max_paste 12-20、prefill）在新战役配置里设，不动默认值（零行为变更原则）。
- **单测**（新增 `tests/test_copy_paste_depth.py`）：合成 image+depth+masks → deposit → 强制 prob=1 贴入 → 断言 (a) 贴入区域 depth/mask/RGB 三方一致；(b) 源深度为 0 的像素保留目标深度；(c) 混合 bank（无深度条目）在有 depth 的 result 中被跳过；(d) bank state_dict v2 往返 + v1 加载兼容。

### P5 — 推理 topk-100 切割（config 化）
- **现状**：代码已支持 `mask_former.inference_topk`（arch.py:653 getattr，默认 100），但 **schema 无此字段**（extra=forbid 配置写了会被拒）——这是真正的缺口。
- **修复**：schema `MaskFormer` 配置段新增 `inference_topk: int = 100`；新战役配置设 200。校准验证在阶段 2 用封存权重重推理完成（topk100 vs 200 配对，c0 锚 +0.55pt）。
- **验证门**：阶段 2 重推理配对差值落地。

### P9 — 口径债（死键接线 + best_aps 存档）
- **证据**：`object_mask_threshold` 全源码零读取（继承自 M2F 上游——上游也仅用于全景分割，实例路径同样硬编码 0.5）；binarization 0.5 硬编码于 gpu_postprocess.py:210；best.pt 仅按 val/mAP 选（AP_s 更优者被跳过）；val 全为 EMA 口径。
- **修复**：
  1. schema `object_mask_threshold` 标注 deprecated（保留解析兼容旧配置，描述注明仅上游全景分割语义）。
  2. 新增 `inference_mask_threshold: float = 0.5` 接线到 gpu_postprocess 二值化（默认 0.5 行为不变；为 R2 阈值扫描 0.45/0.40 提供开关）。
  3. trainer 增加 `best_aps.pt`（按 val/segm_APs 并行存档，含 EMA+raw 双权重，复用 model_best 工件格式，artifact_kind="model_best_aps"）；`best_aps_metric` 进 checkpoint state。
- **单测**：扩展现有 trainer 测试模式（`tests/test_eval_runtime_contract.py` 风格）：模拟 metrics 序列断言 best.pt/best_aps.pt 各自按各自指标更新。
