## 2. 3+4 个改善方案（七场斗兽场 → 胜出形态 → 实现状态）

### P3-a → BAS-CL+（边界带采样 + coverage 软标签）

- **机制**：三段点采样（50% 不确定性段 + 30% GT 边界带[地板 32 点/GT，带宽 r=clamp(√A/8, 1.5, 6)@1024] + 20% 内部/近邻）；标签 = 512² coverage 软图（avg_pool 2×2，与 CF1 反事实构造对齐）；带加权 BCE（**带内点豁免 balanced_ce 的 ~100× 降权**——P3-a 审查发现的代码级关键：fg_ratio clamp 0.01 使小目标边界外侧点不罚，会抵消任何边界监督）+ 带 Dice（λ_b=3，ramp 2K）；几何点包每迭代构建一次、9 层共享；全 GPU 实现免 nonzero 同步。
- **实现位置**：`magformer/models/common/criterion.py`（带采样器含末格离散均匀修复、软标签构造、带内豁免）。
- **预期**：+6~10pt（CF1 上限的 15-40% 回收，五家主张收敛区间）。

### P3-b → ACB（面积守恒二值化）— 未实现

- **机制**：逐掩码求 τ_k（二分或水填充，等价）使二值面积 = 4·Σ_canvas p̂（coverage 软标签使 Σmask_prob 成为 GT 面积的无偏估计——这是 P3-a 的下游依赖）；clamp [0.40,0.52]，大目标护栏 |τ−0.5|<0.03。零学习参数、零训练、推理 +2~3.5ms、关=逐位回基线。
- **依赖声明（预注册）**：BAS-CL+ 校准探针 |4Σp̂−A_GT|≤0.15 不过关则 ACB 塌缩为 null。
- **预期**：+0.8~1.6pt（链级上界 +3.1）。

### P3-c → HDA+（hires 20× LR 退火）

- **机制**：hires 组 20× LR 乘子独立余弦退火 20→1×（主组日程逐字节不动；clip=1.0 下每步更新 ∝ lr，20× 乘子 = 20× 噪声球；退火后 128K 噪声半径降 13.7×）。触发式日程（损失分量斜率检测）防切断 BAS-CL+ 复活的边界信号。
- **实现**：`solver.hires_lr_multiplier` + `solver.hires_mult_anneal`（退火部分）。裁决中的"画布键双 EMA 0.99995"（残余方差 ×0.5）**未实现**。
- **预期**：+0.2~0.6pt。裁决备注：与 P3-a 互为解药（边界加权会放大 hires 噪声），两场本应同栈上线。

### P4-a → mCDN+（小 GT 专用对比去噪）

- **机制**：每图**面积最小 4 GT 保底** + AIM 资格线（≤4096px²）截 M≤8；K=3 噪声阶梯 0.05/0.15/0.30×box（分量式：中心位移 |Δ|≤tier·wh/2、尺寸比 ∈[1−tier, 1+tier]——修复了初版"iid 绝对高斯 43% 退化框"与"抖动被 wh 双重缩放 85× 欠噪"两个实现级错误）；**GT-free 环带验证负**（位移 1.5–2.5× 自身 wh、奇数槽 0.5–2.0× 缩放、真 xyxy IoU 门——修复了初版"cxcywh 当 xyxy 用 IoU 门形同虚设"）；块对角自注意力隔离；DN 行进 matcher 前剥除（匹配逐位不变）；中间层 aux 头只算常规行（开销 +3.6% 而非 +32%）；DN 正样本 cls 目标 = q（承 MAL-CP+）；推理整组丢弃 0ms。
- **实现位置**：`magformer/models/magformer/arch.py::_generate_dn_queries`（选择/阶梯/负样本 + `gt_keep_idx` 配对修复）+ `criterion.py`（DN 配对按 gt_keep_idx 索引 GT 掩码、DN QFL detach）。
- **预期**：+0.5~1.5pt@16K（DN-DETR +1.9 文献锚 ×0.3-0.5 折扣）。

### P4-b → SCB+（种子-回廊 query 拼接）

- **机制**：200 query 池内 64 个种子槽（R2b 种子路线复活）；probe 峰值出生 + α 接生坡道（seed_ramp_iters=4500，防 DDP/cls 头早期不稳）；种子行 probe-fg 注意力先验**贯穿全部 8 层**（修 P6 残余：门控原本只有第 8 层消费）；seed_dropout 0.15（训练期随机关断→导出零开销）；零开销回退档（seed_active=False）。
- **实现位置**：`magformer/models/common/transformer/multiscale_decoder.py`（probe 头、种子槽拼接、先验注入；`_seed_calls` 仅训练期推进——修复了评估也推进导致 ramp 跳变 ~18%/次的错误）。
- **预期**：+4~9pt（覆盖率 61.9→≥88% 为主要兑现通道；MAL-off 臂必须复现 R2b 的 0.29 卡死是捆绑必要性证明）。

### P4-c → MAL-CP+（q 质量目标 + 分层贴入增密）

- **机制**：**C1** q 目标 = matcher 的 dice 代价列免费搭车（"匹配选的就是它，分数学的就是它"），QFL β=2.0、warmup 1000、负样本逐位不动（DEIM 铁律：增密必配 MAL）；**C2** copy-paste 分层贴入（bank 2000 / prefill 800 图 / max_paste 12 / tiny(<64px²) 抽样权重 0.60 / 入库深度 SNR>1.0σ 过滤 / crop 边 ≤192）。
- **实现位置**：`criterion.py`（QFL 构造 + detach 修复）+ `magformer/data/dataset.py::_InstanceBank`（深度通道 v2、prefill、状态恢复）+ `magformer/data/transforms.py::CopyPasteTransform`（深度同步贴入）。
- **预期**：+3~6pt（诚实开销口径 +3~6% 训练时间，含贴入后 AIM 匹配列增长）。

### P4-d → TREX+（桶中位锚定轨迹重排）— 未实现

- **机制**：解码器 9 组逐层预测（`multiscale_decoder.py` aux_outputs）推理时已算出、被 `_inference_raw` 丢弃——轨迹信息零成本。信号 z1-z5（语义持续/空间收敛/跨尺度一致/重复组结构/内外掩码度）→ **桶中位锚定乘法重排**（每面积桶 median(g)=1，数学上不净抬任何桶、只做桶内重排；64-256 桶现有分数 AUC=0.490=零信息，恰是活口）；g clamp [0.7,1.3]；常数 ≤10 个、5 折拟合、全 val 裁决。零训练、核心 ≤0.5ms。
- **预期**：EV +0.15~0.35pt；Gate A（特征 AUC）判死概率 ~50%，判死也是交付。

## 3. B1' 合并实验：配置、过程、失败读数

### 配置与启动

`experiments_archive/v317_next_stage_2026-07/source/configs/aps_20260913_full/g1_b1_merged_16k.yaml`：**五个已实现方案全部同开**（bass + mal/paste + dn + seed/probe + hires 退火），ImageNet 塔预训练 + model_init 头**从零**（不在 128K 权重上续训），4 卡 DDP（GPUs 4-7）bs1/rank 有效 batch 4，lr 1e-5 cosine，计划 16K 步，eval/checkpoint 每 4000。

### 迭代链（详见 `output/aps_20260913/EVIDENCE.md` §16–§18）

r1 首存档被主机 SIGKILL（copy-paste bank 装载态 gather 峰值，首个带 bank 的 4-rank 运行）→ r2 NCCL watchdog 600s 杀（已提到 30min）→ r3 opt6400 再次主机杀（bank 装满 RSS 33GB/rank 单调增长）→ r5（workers 4 + 全核 + malloc trim + 90% 内存上限）稳定 1.41s/it 至 opt≈4700，按用户指令停止。三次教训全部转化为已提交的 infra 修复（gather 前 empty_cache+gc、host_rss_gb 遥测、watchdog 30min）。

### 失败读数（判读核心事实）

**eval@4000**（B1'-r5，首个完整 winners-ON 读数，2026-09-22 15:27）：

| 指标 | B1'（五方案 ON） | A0（winners-off 同协议）@4K | 差 |
|---|---|---|---|
| segm AP | **0.7011** | 0.8675 | **−16.6pt** |
| segm APs | **0.0261** | 0.2656 | **−24.0pt（−90%）** |
| segm APm | 0.6377 | 0.8614 | −22.4pt |
| segm APl | 0.9458 | 0.9756 | −3.0pt |
| segm AP50 | 0.8295 | 0.9701 | −14.1pt |
| segm AP95 | 0.2502 | 0.4296 | −17.9pt |
| bbox AP | **0.1583** | 0.8521 | **−69.4pt** |

- 预注册判读门：B1'−A0 ≥ +1.5pt 才放行 F2；灰区 0~+1.5 推迟；**实际 −16.6pt → 硬失败，F2 封锁**。
- 训练本身健康：损失全有限（dn_ce 0.058 / dn_dice 0.243 / 带 Dice 0.318 / neg_ce 0.016），吞吐 1.41s/it。**异常信号：probe 损失从启动起卡平 ~1.00**（种子 probe 从未学起来），α@4K≈0.89，64/200 查询被种子槽占据。
- **归因未定**（合并启动无法归因）。候选排序：(1) SCB+ 种子拼接（probe 平坦 + 池扰动）；(2) MAL-CP+ 贴入增密（≤12 贴/步、60% tiny，训练分布扰动）；(3) 交互项。**bbox AP 同崩（−69pt）提示是 query 池/数据级扰动，而非单纯损失权重问题**——定位流被毁不可能是边界损失或 q 目标单独造成。

## 6. 新会话建议

1. **不要再合并启动。** 先做归因消融（二分法）：四臂各 4K ≈1.9h（GPUs 4-7）——`winners-off sanity`（预期 ≈0.8675，复核修复后代码基线未漂移）→ `criterion-off`（关 bass+mal）/`arch-off`（关 dn+seed+probe）/`data-off`（关 copy-paste），按差值定位破坏源。配置改法见 g1_b1_merged_16k.yaml 对应开关置 false、max_iter 4000。
2. 或先只跑 `winners-off sanity` 单臂（1.9h）确认基线，再决定逐场引入顺序（建议单场单引入，每场过自己的短训门再叠下一场——这正是 B1' 违反的纪律）。
3. **ACB 与 TREX+ 两个推理侧方案未实现且零训练**：TREX+ 只依赖现有 aux_outputs（封存权重即可验证），不牵涉训练侧成败，可在任何时间独立推进；ACB 依赖 BAS-CL+ 单独过门后的校准探针。
4. 硬规则：只用 GPUs 4-7；251GB 主机同时仅一个 4-rank 束；内存 ≤90%（≈225GB）；杀进程用 `ps aux | grep "[p]attern"` + 按 PID（pkill -f 已三次误杀自身）。
5. 关键锚点速查：c0@fullval 0.8603/0.264；F1@128K 校准 0.8744/0.2700（唯一真实 AP_s 长训锚）；A0@4K 0.8675/0.2656（winners-off 短训锚，权重已清、数值存 docs/data/g1_fail_record_20260922/）；B1'@4K 0.7011/0.0261（失败读数）。
