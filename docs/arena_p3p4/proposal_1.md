# P3-a 提案 #1｜BAS-CL：边界带锚定三段点采样 × 链校准软标签

**提案人**：独立提案人 #1（斗兽场 P3-a，2026-09-21）
**一句话**：把每匹配掩码的 12544 个损失点从"锚定在**当前预测**边界的不确定性采样"改为"锚定在 **GT 边界带**（尺度自适应带宽）的三段采样"，配边界带加权 BCE+带 Dice（带 ramp），并把 BCE 目标从"1024² 硬标签"换成"GT 穿生产渲染链后的 512² 覆盖率软标签"（CF1 反事实的构造对齐）。纯损失/数据侧，推理 0ms，训练 <+1%。

---

## 0. 摘要（判分用）

| 维度 | 内容 |
|---|---|
| 机制 | 监督密度再分配（不是加量）：小目标 GT 边界带的有效监督点从 ~0.2-2 点/次 提到 ~3700 点/次；同时把 BCE 目标搬进模型输出本身的假设类（area-down→bilinear 链的不动点），消除半覆盖 cell 上 0/1 目标的不可实现性振荡 |

## 1. (a) 机制因果链：为什么攻击根因而非症状

### 1.1 症状 → 两条根因链

**症状组**（全部有实测锚）：
- S1：±1px 膨胀/侵蚀都变差（<64 桶 0.652→0.476/0.256）——边界误差是抖动非偏移（[R2 §D4]）；
- S2：高 IoU 段崩塌：AP@0.75=0.247 / AP@0.90=0.018，坍缩的 87% 归掩码内容（[R2 §D1/D5]）；
- S3：matched IoU p50 仅 0.635（<64）/0.674（64-256），frac≥0.75 仅 0.242/0.272，而链可达 0.817（[R2 §D2/D7]）；
- S4：10px 目标每次迭代只落 ~4-47 个采样点且不专门落在边界上（[BRIEF §1]）；边界像素是最高方差预测、hires 组边界噪声球 20×（[SYNTHESIS P7 / P3-c]）。

**根因链 R1（监督密度链，对应子轴"点采样策略"）**：现实现 `criterion.py::_loss_masks`（L445-451）对每个匹配掩码调用 `get_uncertain_point_coords_with_randomness`：75% 点取自 **−|logit| 的 top-k**（不确定性锚定在**当前预测**的软边界），25%（3136 点）全画布均匀。逐点算术：
- 一个 10px 目标在 512 画布上 ≈5×5 cell；GT 边界带（±0.5px@512）面积 ≈16px²。随机段落入边界带期望 = 3136×16/262144 ≈ **0.19 点/次**；
- 不确定性段看不见预测的"自信错误"：预测边界整体偏移 1-2px 后，错位带内 |logit| 大 → 恰好**不被采样**——采样器系统性盲于自己最该受罚的位置；
- 净效果：小目标边界每次迭代的有效监督点 ≈0-2 个，边界梯度 ≈0。这直接解释 S2/S3。
- 针对性反证"只加点数"：num_points 12544→50176（×4 开销 ×9 深监督）只把边界带期望提到 ~0.8 点/次，且不确定性盲区仍在——**密度必须再分配，不能靠加量**（PointSup：~10 个点放对位置 ≈ 全监督 94-98% [调研 [8]]）。

**根因链 R2（目标不可实现链，对应"损失形式"+标签）**：现标签 = `point_sample(1024² 硬 GT)`（`_loss_masks` L452）——除边界 ±1px@1024 的双线性模糊带外是 0/1 阶跃。而模型输出在推理时必须经 `512 logits → bilinear×2 → 0.5`（`gpu_postprocess.py:200-210`）。要求网络在 512 网格上拟合阶跃，等于要求一个平滑函数类（双线性上采样后 ~2px 过渡带）逼近不连续目标：**半覆盖 cell 的贝叶斯最优预测不存在稳定解**——不同迭代/不同实例亚像素配准下目标在 0/1 间翻转，梯度永不收敛，边界像素方差最高（S4）。这直接解释 S1（抖动）与 S2。R4 的 lr 退火（P3-c）只能消优化器噪声分量，消不掉这个**目标本身的冲突**。

### 1.2 为什么本方案攻的是 R1+R2 本身

- 子轴一（三段采样）直接消灭 R1 的"0.19 点/次"：边界带采样点 = 30%×12544 ≈ **3763 点/掩码/次**，密度提升 ~3 个数量级，且锚定 GT 边界（不依赖预测质量）；
- 组件三（链校准软标签）直接消灭 R2：软标签 = `area-down(GT,512)` 的覆盖率场 ∈[0,1]，0.5-等值线 = 面积多数决边界；它**恰是模型自身渲染链作用在 GT 上的不动点**（对它做 bilinear×2+0.5 二值化 = CF1 掩码），目标在网络假设类内、贝叶斯风险可达 0，梯度从振荡转为收敛；
- 子轴二（带加权 BCE+带 Dice）把新增密度转成**幅度可控**的边界梯度（尺度归一、带 ramp），并补上 BCE/Dice 都罚不到的"错位方向"信号（Kervadec [调研 [1]] 的点采样版）。

不做的事（反面教训对照，[调研 §4]）：不加精修头（RefineMask 收益集中大目标 +6.0 vs +1.5 [11]）；不加固定 trimap（Boundary IoU 论文自证固定带宽对小目标失真 [23]，本方案带宽尺度自适应）；不动二值化阈值/链（那是 P3-b 的 4.0pt，CF2−CF1 实测 [R2 §D5]）；不引入 focal（单类极小目标有塌 0 风险 [30]）。

## 2. (b) 与二分匹配 / set-prediction 的兼容性论证

1. **代价矩阵零改动**：`matcher.py::forward`（L356-453）的均匀 12544 点 + AIM 小 GT 列（`_aim_small_gt_costs`，L276-354，已去 16-GT 帽）原样保留。step-0 的匹配动力学与基线逐位一致，不存在损失→匹配的反馈回路改动。
2. **损失严格后置于匹配**：本方案只改 `SetCriterion._loss_masks` 内"每个已匹配 (query, GT) 对"的点分布与逐点权重——逐对独立、无跨 query 耦合，保持 set 预测的置换不变性；o2o 主匹配结构不动。
3. **梯度尺度不变**：逐点权重按掩码归一化到均值 1（`w ← w/mean(w)`），`loss_mask` 仍是 `sum/num_masks` 口径，cls/mask/dice 权重比与 `eos_coef` 平衡不被扰动，无需重调 lr 主尺度。
4. **×9 深监督一致性**：辅助层（256²）与最终层（512²）共用同一套归一化坐标（`point_sample` 按归一化坐标工作，分辨率解耦——现实现已如此），aux 各层匹配结果不同不影响（GT 点包按全量 GT 预构建，见 §3.4）。
5. **DN 支路不动**：`_compute_dn_loss`（L584-726）保持均匀采样（后续可选扩展，默认关闭，保证单因子）。

## 3. 方案设计

### 3.1 子轴一：GT 边界带锚定三段点采样（尺度自适应带宽）

每个匹配掩码的 12544 点重配为三段（比例可配，默认 50/30/20）：

| 段 | 占比 | 来源 | 作用 |
|---|---|---|---|
| 不确定性段 | 50% | 保留 M2F 原生 `get_uncertain_point_coords_with_randomness`（6272 点，锚定预测） | 粗收敛 + 内部内容 + 大目标主梯度（M2F 原文证明不掉点 [9]） |
| **GT 边界带段** | 30% | 从该 GT 的带池（|到 GT 边界| ≤ r_i）逆 CDF 均匀采 3763 点 | 边界监督密度 ×10³（R1 解药） |
| GT 内部+近邻段 | 20% | 2/3 从 GT 内部池、1/3 从 bbox+30% margin | 保覆盖率/防塌缩（Kervadec 区域项教训 [1]） |

- **带宽尺度自适应**：在 512 画布上 `r_i = clamp(round(√area_512 / 8), 1, 3)` px——<64px² 目标 r=1（整个目标≈全是边界），512² 级目标 r=3 封顶。规避固定 trimap 失真 [23][4]。
- **全 GPU、无 host sync**：带/内部池不用 `.nonzero()`（会强制同步），用 `cumsum + searchsorted` 逆 CDF 采样（`idx = searchsorted(cdf, rand(P)·cdf[-1])`），全程留在 GPU。
- 关键性质：采样锚定 **GT** 而非预测，对"预测边界整体偏移 1-2px"的自信错误照样采样——补上不确定性采样的结构性盲区。

### 3.2 子轴二：边界带加权 BCE + 带 Dice（可独立开关，带 ramp）

- **带加权 BCE**：逐点权重 `w(p) = 1 + λ_b·1[p ∈ GT 带]`，按掩码归一化均值 1 后乘进现有逐点 BCE（与 `balanced_ce` 的 fg/bg 权重相乘兼容——后者本就从 `point_labels` 现算，L471-482）。λ_b 默认 3，**前 2K it 从 0 线性升满**（Kervadec α-ramp 防塌缩教训 [1]；区域项保留 ≥70% 点位+全量 Dice 不动，双保险）。
- **带 Dice（Boundary-DoU 的点采样版）**：新增损失键 `loss_dice_band`：Dice 只在带内点集上算（pred∩带 vs GT∩带），权重走同一 ramp（0→1.0）。对 <64px² 目标，带≈全目标+±1px 邻域——正是 ±1px 抖动（S1）生活的区域；对大目标等价于尺度自适应 trimap Dice [4]。
- 与 Kervadec 原形式的差别及为什么在我们的数字结构下更好：Kervadec 是稠密积分的距离加权——在固定 12544 点预算下**加权不能凭空造出落在带内的点**；<64px² 目标全部前景点距边界 <2px（w≈max 处处成立）而点数只有 ~1-10 个，纯加权几乎无增益。**密度（子轴一）与幅度（子轴二）必须同 commit**——这正是本场"两个子轴可组合"的实质。

### 3.3 组件三：链校准软标签（CF1 构造对齐）

- 把 BCE/Dice 的标签源从 `point_sample(1024² 硬 GT)` 换成 `point_sample(GT512_cov)`，其中 `GT512_cov = F.interpolate(GT_1024, 512, mode="area")`（2×2 精确平均 = 覆盖率 ∈[0,1]，与 R2 `analyze2.py` D 段修正后的渲染协议逐位同义，天然无 INTER_AREA/4 bug [R2 §D0]）。
- **构造对齐**：对 `GT512_cov` 施加推理链（bilinear×2 + 0.5）恰得 CF1 的"GT 穿链"掩码——即 27.1pt 缺口的 oracle 定义本身。模型完美拟合软标签 ⟺ 推理输出 = CF1 掩码 ⟺ 拿满 CF1 的 0.5636。训练目标与验收上限**同一构造**，无"标签-评测错位"（评测仍用 1024 硬 GT，CF1 已实测该口径下 0.5636 可达 [R2 §D5]）。
- **可学性论证（超出所引文献的针对性部分）**：软标签在模型输出函数类内（area-down→bilinear 是模型自身链），半覆盖 cell 的目标从"0 或 1 的翻转"变为"稳定的 0.4/0.6"，消除 R2 的振荡梯度源——直接对症 S1 抖动与 S4 边界方差。文献里 [调研 [25] 候选4] 只给了"按构造定义"，本提案补上了假设类/贝叶斯可达性机制与 ±1px 抖动的解释链。
- 辅助层（256²）共用同一 512 软图（归一化坐标采样，分辨率解耦）；如需更狠可对 aux 渲染 256 版，默认不做（保持单因子）。
- 硬标签混合保险：`soft_label_mix ∈ [0,1]`（默认 1.0，即全软；消融可 0.5），防软标签与硬评测间的意外偏差。

## 4. (c) 理论收益上界与依据

**硬上限**：CF1 = +27.1pt（0.2925→0.5636，检测集合/分数/其余掩码全冻结，[R2 §D5 / SYNTHESIS §一]）。CF2−CF1=4.0pt 属渲染链（P3-b 域），本方案不主张；<64px² 桶掩码侧已无可救（CF2 该桶 0.0784 曲线全平，堵点在检测集合 16.5pt，[R2 §D5/堵点表#2]）——**诚实地把预期主战场放在 64-1024px² 子桶**（它们全部计入 COCO-small 口径）。

**分桶结构论证（本提案的针对性数字逻辑，超出调研文献）**：CF1 增量按子桶：64-256px² +18.7pt、256-1k px² +33.2pt、<64 +2.7pt（[R2 §D5]）——**绝对缺口最大的恰是中大桶的边界质量**，而它们正是"边界带采样+软标签"收益最直接的对象（边界弧长 20-100px@512，当前均匀+随机段落带期望仅 ~1-15 点/次，本方案 3763 点）。<64 桶的收益主要变现为 matched IoU 0.635→0.72+（为 P4-a/b/c 恢复检测供给后的复利做铺垫，见 §7）。

**文献锚（均注出处）**：
- Kervadec 边界损失：ISLES 小病灶 DSC +14.8pt、HD95 减半 [调研 [1]]（3D 医学稠密损失，非同场景）；
- M2F 系最贴近证据：植物单类小目标（杂草）仅加边界损失 PQ_weed +2.0、推理零开销 [调研 [21]]；
- M2F 点损失+重要性采样不掉点省 3× 显存 [调研 [9]]（但其成立前提是 COCO 尺度目标带内点数充足；我们 10px 尺度下"点损失不掉点"假设失效——这正是再分配的理由）；
- 调研综合保守估计：纯边界损失可回收缺口的 1/4-1/3 ≈ +7-9pt [调研 §3 候选2]。

**本提案主张值**：全包（采样+权重+软标签）**+6~10pt**（rescore 口径 AP_s，0.2925→0.35-0.39），置信度中高；分项判读数字：matched IoU p50：<64 0.635→≥0.72、64-256 0.674→≥0.74、frac≥0.75（<64）0.242→≥0.40；AP_s@0.75 0.247→0.35-0.45（CF1 该点 0.6023 为上限 [R2 §D5]）；AP_s@0.90 0.018→0.05-0.10（CF1@0.90=0.5267 为上限）。附带红利：软标签使掩码内部概率校准 → maskness 分数被结构性压低的程度减轻（score p50 随桶 0.613/0.723/0.821，[R2 §D2]），与 P4-d 正向叠加。

## 5. (d) 开销预算（算式）

**训练（每迭代，N_gt ≤ 41 = train p90 [SYNTHESIS P1]）**：
- 点包构建 ×1：`area-down`（41×1.05M 读+0.27M 写）+ 2×maxpool 3²（41×0.26M×9×2 ≈ 0.19 GFLOP）+ 比较 ≈ **0.25 GFLOP ≈ 0.3-1ms**（含 ~15 次内核启动）；
- 9 次损失调用增量：cumsum(41×0.26M)≈10.7M 加法 ≈0.1ms×9；searchsorted+gather+cat（~80K 查找）≈0.05ms×9；带 Dice/权重归约（N×12544 向量）≈0.03ms×9；标签 point_sample 由 1024² 硬图改 512² 软图——**中性偏省**；合计 ≈ **1.5-2ms**；
- **总增量 ≈ +2~4ms/it（含裕量 <10ms）= 1.44-1.60 s/it 的 +0.2~0.6%**，红线 +20%（288-320ms）的 **1/30 以下**。

**显存**：pack 常驻 ≈43MB（fp16 软图 41×0.26M×2B≈21MB + 带/内部 bool ≈22MB）+ cdf int32 暂存 43MB → **峰值 +~90MB ≪ 24GB/卡**。

**推理**：**+0ms**。criterion 不在推理路径；`gpu_postprocess.py`/`arch.py::_inference_raw` 零改动；配置仅训练侧。可由"冻结权重+新损失路径 forward，val dets.json 逐位一致"直接验证（§6 探针 P0）。

**GPU 优先合规**：全程 maxpool/interpolate/cumsum/searchsorted/grid_sample 在 GPU；唯一潜在同步源 `.nonzero()` 已用逆 CDF 规避（单测断言，§6）。

## 6. (e) 正确性验证方案

**P0 单测（CPU，pytest，不占卡）**：
1. **no-op 回归**：全开关=0 时 `_loss_masks` 输出与基线逐位一致（fp32 容差 1e-6）——保证"关掉=基线"；
2. **软标签构造**：与 `analyze2.py` D 段渲染协议一致（`mode="area"`、无 /4）；部分覆盖 cell ∈(0,1)、全覆盖 ≈1、空 ≈0；对软图施加 bilinear×2+0.5 后与 CF1 掩码 IoU=1（构造自证）；
3. **带池**：5×5@1024 合成目标 → 512 上 r=1 → 带大小 ≈ 周长×带宽；逆 CDF 采样点 100% 落带内；
4. **无同步断言**：`torch.cuda.set_sync_debug_mode("error")` 下跑一遍 `_loss_masks`（可用 CPU mock）；
5. **权重归一**：mean(w)=1/掩码；空图、1px GT、41-GT p90 容量不炸。

**P1 冻结基座零训练探针（~15min GPU）**：sealed F1 权重 + 新损失路径 forward-only：val dets.json 与封存件逐位一致（证明推理零污染、"0ms"成立）；损失值漂移幅度符合手算预期。

**P2 ≤16K 短训门（裁决实验室，sealed F1 last.pt resume，4 卡 DDP，lr 1e-5 平坦尾段，单因子）**，最小 3 臂：control（原样 resume）/ 仅采样（boundary_point_ratio=0.3，其余 0）/ 全包：

| 判读指标 | 基线 | 8K 通过线 | 16K 通过线 |
|---|---|---|---|
| matched IoU p50（<64px²） | 0.635 | **≥0.70** | ≥0.72 |
| matched IoU p50（64-256px²） | 0.674 | ≥0.71 | ≥0.74 |
| AP_s@0.75（rescore） | 0.247 | **≥0.30** | ≥0.35 |
| AP_s@0.90 | 0.018 | ≥0.04 | ≥0.06 |
| 护栏：AP_s@0.5 | 0.6036 | ≥0.59 | ≥0.59 |

判读规则：仅采样臂过 8K 门 → 采样主导、开销取下限；需全包才过 → 标签项必要；AP@0.5 护栏破 → 预案降 `boundary_point_ratio` 0.3→0.25 或 λ_b 减半（ramp 已防急性塌缩 [1]）。附加观察：hires 组边界 lr 噪声指标（P3-c 口径）是否被软标签压低——若是，写入 P3-c 叠加证据。成本：3 臂 × 8K × 1.5s ≈ 3×3.3h（4 卡），16K 复核仅对过线臂加跑。
