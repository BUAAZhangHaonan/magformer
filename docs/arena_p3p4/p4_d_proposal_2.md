## 0. 主张（一段话）

当前导出链把两份**已经算出来又被扔掉**的信息丢弃了：(i) 解码器 8 层的逐层预测轨迹（`aux_outputs`，`multiscale_decoder.py` L824-1046 逐层产出 cls/mask/box，`arch.py _inference_raw` L1493 只取最后一层）；(ii) 掩码置信的内部/边界空间结构（`postprocess_tensors` L212-217 用一个标量均值抹平）。本提案把切割点从"裸 cls topk"移到"新融合分 topk"之后，用三类新信息——内部掩码度（解耦边界拖拽）、解码轨迹三信号（CQTR 的原生移植）、重叠簇重复沉降——重建导出分数与导出成员。其资格在于：这些变量**在 TP 与 FP 之间（尤其 AUC=0.490 的 64-256 det 桶）携带现有分数不含的排序信息**，而非对既有分数做单调变换。r1_score 反事实上界锚定：重打分通道 ≤+1.3~1.6pt AP_s，存在性通道由 G0 实测的 oracle-200 锚定（先验 ≤+0.5pt）。点估计收益 **+0.4~1.0pt AP_s**，全部离线可裁决。

## 1. (a) 机制因果链：为什么新信息能改变排序，而单调变换不能

### 1.1 死家族的机理回顾（为什么必须引入新变量）

AP 对逐 det 分数的任意**严格单调变换不变**。已实测全灭的三条（分位重标定 −13.1 / score=IoU −11.9 / oracle 版桶校准 −2.9，`reviews_20260920/r1_score/report.md` §1）的共同点：要么是既有分数的函数（无新信息），要么用的是部署时不可得的 oracle 信息（IoU 需 GT）。且 <64px² det 池 80.5% 是 hard-FP、每个被命中小 GT 平均挂 **14.05 个** IoU≥0.5 的重复 det——任何**无条件**抬小桶分数的变换都让 FP 与重复搭车。结论（R1 原话）："只有每 GT 一个代表、代表按质量排、冗余沉底才有增益"。

### 1.2 本提案引入的三类部署时可得的新信息

**新信息 A：掩码置信的内部/边界分解（maskness 解耦）。**
现状 `m = mean_{p∈B} σ(logit_p)`（B=二值掩码）把边界像素与内部像素平均在一起。小掩码几乎全是边界：理想 12-20px 掩码的 m 上限仅 0.95-0.96（大目标 0.99），stride-2 画布上 tiny 掩码 ~0.85-0.9（EVIDENCE §5；简报 §7）。matched 分数 p50 随桶单调 0.613/0.723/0.821、TP 分数中位 <64px² 桶 0.29 vs 大目标 0.80——**这个 2.7× 压差里有相当部分是几何伪影而非证据强度**。分解为 `m_int`（距边界 ≥2px 内部像素均值；tiny 掩码回退 d0=1→全掩码均值）+ `m_bnd`（1px 边界环均值），再除以离线拟合的面积桶上限 cap(A)。**为什么不是变体 (c)**：两个旧分完全相同的 det，m_int 可以不同（空间结构差异）；且 cap 归一只作为联合融合的一项与轨迹信号相乘，其净效应由直接以 AP_s 为目标的离线拟合决定——FP 搭车在拟合目标内被直接惩罚。R1 堵点表 #4 锚定该因子单独直接收益 ≤0.5pt，本提案不指望它单独成事，只作为融合配方的一项。

**新信息 B：解码轨迹三信号（CQTR 的原生移植，arXiv 2609.06581）。**
CQTR 在 9 个冻结检测器×3 数据集上以"反事实尺度干预 + 解码轨迹（空间收敛/语义持续/跨尺度冲突）"零训练重打分，APs +1.95~3.81（TinyPerson 最高 +3.85）。其输入级尺度干预（一次缩放重前向 ~+60-70ms）超本場预算，**不可部署**；但我们的解码器原生提供了等价的轨迹源——逐层 `predictions_class/mask/boxes`（9 个时间步：初始+8 层），当前被丢弃：
- **T1 语义持续**：末 3 层 cls sigmoid 的斜率与持高层数。真 keeper 的 cls 逐层上升并驻留；"喷洒"出的 13 个重复 query 是晚层闪现（末层才被互抑制的注意力推向同一 GT），轨迹断续。
- **T2 空间收敛**：逐层 `pred_boxes`（`box_embed` 每层已算，`forward_prediction_heads` L1060）中心漂移归一化。锁定早、漂移小的 query 可靠；跨层振荡的是重复/虚警。
- **T3 跨尺度一致性**：解码层在 stride 8/16/32 循环、末层消费 stride-4（L859-867）——逐层掩码本身构成一次**前向内多尺度扫描**，是 CQTR 尺度干预的原生替身。层间二值掩码（stride-2 子采样画布上）的一致性即跨尺度冲突信号；真小目标在 32/16/8/4 各尺度视图上一致，纹理硬 FP 跨尺度冲突。
- 离线对照锚：验证期额外做一次真·输入级尺度干预（0.75×/1.25× 重前向，仅诊断），量化原生 T3 与干预版的差距；部署版只用原生信号。

**新信息 C：重叠簇结构（重复沉降的软版）。**
14.05 det/命中 tiny GT 的"喷洒"结构本身是可观测信息：对每 det 取与更高分 det 的最大掩码 IoU `d_q`（box-IoU 预筛后仅对高重叠对算掩码 IoU），乘高斯沉降因子 `exp(−(d_q/τ)²)`（soft-NMS 家族；τ 离线拟合）。这是对 **R1 判定的最优排序形状**（"冗余沉底"）的部署时近似，oracle 锚 +0.26pt（`dedup_fixed`），且与 (a) 重复 det 排在 keeper 之下所以"重复本身不伤 AP"的观测一致——它伤的是后续一切提分方案的池纯度，先沉降再融合两者兼得。

### 1.3 排序价值存在的直接证据

det 面积 64-256 桶现有分数 **AUC=0.490（纯随机）** 且 matched 占 30.1%——该桶任何 AUC>0.55 的新信号都是纯增益；<64 桶 AUC 0.753 也有抬升空间（R1 §3 表）。轨迹信号的 TP/FP 不对称有结构理由（1.2-B），但**本地 AUC 尚未实测**——这正是验证方案 G1 的第一道门：信号不行就自杀，不进实验室。

### 1.4 存在性通道（改变池成员，而非只重排）

现状切割发生在裸 cls 上、maskness 融合**之前**（`arch.py` L1539-1540；`gpu_postprocess.py` L184-185）：小目标 query 的 cls（推算 ~0.45-0.55）在 200→100 切割时被吞。topk200 实验（+0.09）**没有关闭这条通道**——它保留全部 200 个 det 后由评估器按**旧融合分**截断，小 det 在旧融合分下仍进不了 top-100。若切割改用**新融合分**（在 512² 画布上先算完全部 200 query 的分数再取 100），成员即被更换。其上界 ≠ R1 的 +1.6pt（那是对已导出 100 池的 oracle），而是 oracle-200，需 G0 实测。配套**有界小面积配额**（Arm C）：从新分排名第 101-140 的小面积 det 中按新分补入 ≤Q∈{4,8} 个——配额本身不是新信息，它是轨迹信息的交付载体（被补入者的 TP 率由新分决定，而非 80.5% 基率）；被挤出的是旧分池底（hard-FP 中位分 0.063 的垃圾），R1 `fp_sanitize` 锚定其损失 ≤0.07pt。

## 2. (b) 与 set-prediction / 导出契约的兼容性

1. **训练与匹配零改动**：不碰二分匹配、AIM、损失、query 语义。set-prediction 的 o2o 结构在训练侧定义，本提案只作用于冻结权重的推理导出端。
2. **导出契约保持**：每图仍输出 ≤100 个 (score, 单类, RLE mask)；掩码生成链（gather→双线性×2→sigmoid→0.5 二值化→RLE）**逐位不动**——已关闭的阈值分支保持关闭。变化的只有 (i) 分数定义（仍是 [0,1] 的合法排序键）与 (ii) top-100 的选取键。评估协议（maxDets=100、按分截断，commit 4ebc733a）与现行语义完全一致：我们只是把"按什么分截断"换成更好的分。
3. **无 NMS、无后处理依赖**：重复沉降是分数乘法（软沉降），不删除 det、不引入 NMS 算子；set-prediction 的免 NMS 性质保留。
4. **CUDA-graph / GPU 导出链兼容**：新增算子全部 shape-static（固定 200 query、固定 512² 画布、固定常数），`postprocess_tensors` 的可捕获性保持；`DeferredExportRing`/pinned 传输机制零改动（`gpu_postprocess.py` L374-477 不触碰）。改动集中在 `postprocess_tensors`（L156-226）与 `_inference_raw`（L1485-1593）的同一算子序列两处镜像，eager 与 graph 路径继续 bit-identical。
5. **部署语义注记**：新分数不再是"cls×maskness"的旧标定，若下游有绝对阈值消费者，可在标定集上追加一次保序等张映射（对 AP 无影响，秩不变）。COCO 评估只消费秩，无契约冲突。
6. **回归保护**：旧 top-100 成员的掩码 RLE 必须与封存 dets 逐位一致（G4 回归测试），证明掩码链未被波及。

## 3. (c) 理论收益上界与依据

基线锚：封存 F1@128K EMA 标准协议 **mAP 0.8744 / AP_s 0.2700**（`docs/2026-09-21-f1-128k-calibrated.md` §二）。R1 的反事实在 112K dets 上测得（自定义 <64px² 桶口径，AP_s base 0.2925），相对量迁移如下：

| 通道 | 上界（pt AP_s） | 依据与出处 |
|---|---|---|
| Arm A 重排（当前 100 池内重打分） | **+1.33~+1.61**（oracle） | R1 §1：`a_plus_dedup_ranked` 0.2925→0.3058（+1.33）；AR_s 锚 0.3086（+1.61）。AR 上界同时说明：重排通道**不可能超过**此数——CQTR 文献量级（+1.95~3.81，arXiv 2609.06581）不可整体迁移，只能取其"轨迹信号携带真实排序信息"的定性支撑。 |
| Arm A 成员更换 + Arm C 配额（存在性） | **G0 实测**，先验 **+0.1~+0.5** | 上界=oracle-200−oracle-100（待测）；旧分下边际池极薄的证据：topk200 仅 +0.09（校准报告 §二）。 |
| Arm B 重复沉降 | **+0.26**（oracle） | R1 §1 `dedup_fixed`；软部署版取其一部分 +0.1~0.2。 |
| maskness 解耦单独直接效应 | ≤0.5 | R1 堵点表 #4（`a_separate` TP/FP 完全分离也只 +0.5）；本提案只将其作为融合项。 |
| **合计点估计** | **+0.4~+1.0**（点估）／ **+1.6~+2.1**（含存在性的乐观顶） | oracle 通道按 25-60% 兑现率折算；无任何通道时（G1 失败）退化为 0。 |

诚实声明：本场所有通道的 oracle 总和 ≤ ~2.1pt，**不是** 27.1/16.5 两座大山（掩码内容与存在性+分数的训练侧缺口）的替代品；P4-d 是零训练档位的存量变现，按执行顺序先行（BRIEF.md 执行顺序节）。

## 4. (d) 开销预算

### 4.1 推理增量（GPU，算式）

改动结构：对全部 200 query 在 **512² 画布**上算 m_int/m_bnd（替代现状对 100 det 在 1024² 上算 maskness）→ 轨迹信号（逐层 box/logits 免费；掩码矩在 stride-2 子采样画布）→ 新融合分 → topk(100) → 获胜者走原 1024² 上采样/二值化/导出（不变）。

| 项 | 算式 | 流量/耗时 |
|---|---|---|
| 200×512² maskness（fp16，3 遍读写） | 200×262,144×2B×3 ≈ 314MB | ≈0.8ms @400GB/s |
| 轨迹掩码矩（9 层×200×256²，2 遍；box-only 变体=0） | 9×200×65,536×2B×2 ≈ 472MB | ≈1.2ms |
| 簇内掩码 IoU（box 预筛后 ~200 对×256²） | 200×65,536×2B×2 ≈ 52MB | ≈0.13ms |
| 逐层 logits/box 归约 + 重 topk(200→100) | ~36K 元素 | <0.2ms |
| **合计 Δ** | | **≈ +2.3ms（p50），≤+4ms（p99，fp32 翻倍）** |

附注：旧路径的 maskness 在 1024² 上对 100 det 计算（105M 元素），新路径分数因子在 512² 上对 200 计算（52M 元素）——分数因子计算实际**更便宜**；净增主要来自轨迹与未导出 100 query 的画布遍历。全部 GPU、无新增 DtoH 往返（常数在侧流之外）；shape-static 可捕获。对比红线 +10ms 与现状 ~150ms：预算内，且与降到 ~100ms 的目标不冲突。

### 4.2 零训练声明与一次性拟合成本

- 冻结 EMA 权重（`best.pt` model_state_dict；raw backup 仅作离线诊断的跨视图信号，不部署）。
- 一次性拟合：≤8 个标量，坐标上升直接最大化标定集 AP_s（无梯度、非训练）；标定集 = 训练拆分 500 张（无增广）或 CQTR 式 100 张无标注，**两者都跑并报告分歧**；任何情况下不碰 val 3276。成本 ~2-4 GPU·h 一次性。
- 融合包含恒等点（全部权重=0 时退化为 cls×m）——最坏情况是无操作，不会反向伤害。

## 5. (e) 正确性验证方案（封存权重/dets 上离线，零训练）

**数据与资产**：封存 dets `output/aps_20260913/p5_runs/f1_seal_128k/coco_instances_results.json`（3276 图）；GT `magformer_datasets/20260318_1K_32254/annotations/instances_val.validated.json`；封存权重同目录 `best.pt`。评估器：pycocotools 标准 COCOeval（R1 同款，segm，maxDets=100），配 R1 的 <64/64-256/256-1024 面积分桶读数。

**Phase 0 · 一次性转储（GPU，~2-3h）**：封存 EMA 权重对 val 3276 重前向，逐图转储：全部 200 query 的最终掩码 RLE（导出分辨率）、逐层 cls logits（9×200）、逐层 boxes（9×200×4）、画布级 m/m_int/m_bnd、box-IoU>0.6 对的掩码 IoU。另做 0.75×/1.25× 输入干预前向（仅诊断 T3 上界）。复用 R1 `analyze*.py` 骨架（CPU 侧全部后续分析，每 run ~30min）。

**G0 · 上界标定（CPU）**
- B1 oracle-100（重排+oracle 去重，复刻 R1 至 128K）：预期 +1.0~1.6pt AP_s。若 < +0.8pt，本提案整体降级为边缘并终止。
- B2 oracle-200（完美分+oracle 去重+每图截 100）：存在性总上界。若 B2−B1 < +0.2pt → **Arm C 与成员更换通道关闭**，只保留重排臂。

**G1 · 信号质量门（反搭车门，CPU）**：按 det 面积分桶算各信号及融合分对 TP(maxIoU≥0.5) vs hard-FP(IoU<0.3) 的 AUC。**通过条件：融合分 AUC 在 64-256 桶 ≥0.60（基线 0.490）、在 <64 桶 ≥0.78（基线 0.753），且至少 2 个单信号在任一桶 AUC ≥0.58。不达 → Arm A/C 自杀，仅 Arm B（≤+0.26pt）可带条件存活。**

**G2 · 拟合融合主实验（CPU eval）**：常数在标定集拟合（4.2 协议），val 上标准协议评估。**判读数字与通过门**：

| 指标 | 基线 | 通过条件 |
|---|---|---|
| AP_s | 0.2700 | **Δ ≥ +0.30pt** |
| segm mAP | 0.8744 | Δ ≥ −0.10pt |
| AP_m / AP_l | 0.8655 / 0.9769 | Δ ≥ −0.10 / −0.20pt |
| <64px² 桶 AP | G0 重测 | 方向为正 |
| 反搭车证据 | — | <64 桶 hard-FP 分数中位升幅 ≤0.05 且 TP 中位升幅 ≥0.05（重演变体 (c) 即否决） |

**G3 · 臂消融**：A（重排+成员更换）；A+B（+重复沉降）；A+B+C（Q∈{4,8}）；每臂须不劣于 G2 通过配置；最终推荐 = 通过门的最小组件组合。

**G4 · 链路回归**：旧 top-100 成员的掩码 RLE 与封存 dets 逐位一致；eager 与 gpu_export 路径分数 bit-identical（沿用现有双路径校验惯例）。

**判读的预注册**：所有拟合不接触 val；固定种子；正/负结果同样入档（含 G1 自杀情形）。

## 6. (f) 与其它场的叠加兼容性

| 场 | 交互 | 兼容性 |
|---|---|---|
| **P3-a** 边界监督 | 边界更锐 → m_int/m_bnd 分布整体上移 | 正交。cap(A) 与融合权重按 4.2 协议一次性重拟合即可；边界质量提升反而让内部分解更稳定（共生）。 |
| **P3-b** 小掩码表示/软导出 | 若导出改软掩码或面积自适应阈值，分数因子定义需随之改 | 兼容但**声明为联合重拟合点**：m_int 在概率图上仍可计算；若表示换成 DCT/频域，画布级 maskness 需重定义（预注册的适配成本）。 |
| **P3-c** 边界稳定性（lr/EMA） | 只改权重 | 正交；边界抖动收敛后轨迹信号 T1-T3 信噪比提升（共生）。 |
| **P4-a/b**（o2m 辅支路、种子 query） | 均训练期专用、推理丢弃 | 正交：轨迹定义在生产 200 query 上，与训练期辅助结构无关；种子 query 若上线，"早锁定"query 的 T2 收敛信号更干净。 |
| **P4-c** MAL/分数成型 | 抬高小 TP cls，与本提案 g(A)·cap 修正部分重叠 | 恒等保护（4.2）使融合在信号饱和时自动退化为无操作，不与训练侧收益打架；Arm B 重复沉降与 P4-a 只部分覆盖的喷洒结构互补，长期保留价值。 |

叠加顺序：P4-d 零训练先行变现存量（本场）；训练侧各场胜出后，本提案常数按同一协议重拟合一次（~2-4 GPU·h），机制本身不失效。

## 7. 风险与预注册 kill criteria

1. **轨迹信号本地失灵**（CQTR 是外部锚、且新作证据分层低——调研 B §4.8）：8 层深精化解码器的轨迹可能已高度平滑，AUC≈0.5。→ G1 自杀，成本仅 Phase 0 转储。
2. **小桶融合重演变体 (c)**：cap(A) 归一若无条件抬桶，FP 搭车。→ G2 反搭车判读（hard-FP 中位监测）+ 拟合目标即 AP_s 本身。
3. **存在性池太薄**：topk200 +0.09 已示警。→ G0-B2 直接量死。
4. **m_int 对 tiny 掩码空集**：<2px 内部的掩码回退链（d0=1→全均值→桶常数），预注册在融合拟合内。
5. **标定集泄漏争议**：同时报告"训练拆分 500 张"与"100 张无标注（CQTR 协议）"两版常数与 val 结果；若分歧 >0.2pt，以无标注版为准。
6. **mAP/AP_l 回退**：融合对大 det 须近似恒等（大面积下 g≈1、t 饱和≈1）；G2 门 −0.10/−0.20pt 兜底。
