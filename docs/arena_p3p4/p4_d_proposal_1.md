# P4-d 提案 #1：TRS+D —— 解码轨迹可靠性重打分 + 掩码簇去重（零训练导出端机制）

- 场：P4-d 导出与分数融合（topk 切割 × maskness 压分）
- 提案人：独立提案人 #1 / 5（互不可见）
- 日期：2026-09-21 ｜ 属性：**零训练**（冻结 EMA 权重，允许一次性离线常数拟合）｜ 纸面轮，未跑实验
- 判分自述：理论收益上界 **+1.6~1.8pt AP_s（标准口径）**，期望落地 **+0.3~0.8pt**；推理增量 **+2~5ms**（预算 ≤+10ms）；置信度中（0.4~0.5 概率过 +0.2pt 门）；全部验证在封存权重/dets 上离线完成（≤1.5 GPU-天）。

## 0. 一句话主张

把导出排序键从 `cls × maskness` 换成 `cls × maskness × 轨迹可靠性 P`（P 来自**推理时本已算出但被丢弃**的 8 层解码器中间预测），再叠加一个只降不升的掩码簇去重（soft mask-NMS）。P 是每 query 的解码动力学函数而非最终分数函数，因此能改变排序——这正是被证伪的单调重标定家族做不到的事。

## (a) 机制因果链：为什么新信息能改变排序，而单调变换不能

### a.1 已证伪家族的死因解剖（本提案的立论起点）

R1（`reviews_20260920/r1_score/report.md` §1）三个反事实全部崩塌，且死因各不相同：

| 变体 | 结果 | 死因 |
|---|---|---|
| (c) 分位重标定 | −13.1pt | **桶级常数提升**：det<64 桶 80.5% 是 hard-FP（分数中位 0.063），整桶抬分 = ~13.7K 个 FP 搭车到 0.9+ |
| (b) score=IoU | −11.9pt | **按质量排序**：每个被命中 <64 GT 平均挂 14.05 个 IoU≥0.5 det，高 IoU 重复排在唯一 TP 前面，高阈值处制造 FP-before-TP |
| (c″) oracle 只校准 matched | −2.9pt | 即便 oracle 版，抬上去的低 IoU TP 在高 IoU 阈值处也变成排在真 TP 前面的 FP |

同时 AP 对**全局单调**分数变换不变（Rank-DETR 立论出发点；调研C §4.1）。结论：任何 P4-d 机制必须同时满足三个存活条件——(i) **每 query 粒度**而非桶级常数（FP 必须逐个挣到提分）；(ii) **不是纯质量信号**（质量高的重复 det 必须沉底而非浮顶）；(iii) **携带 (cls, maskness) 之外的信息**。

### a.2 TRS 的信息来源：解码器轨迹（今天已被算出并被丢弃）

代码事实（本提案的零成本根基）：

- `magformer/models/common/transformer/multiscale_decoder.py:281-324`：解码器循环对全部 200 query 逐层产出 `predictions_class` / `predictions_mask`（初始头 P0 + 8 层 P1..P8，共 9 组），**推理时全部物化在显存中**（每层前向预测头是注意力掩码的必需副产物），随 `aux_outputs` 返回；
- `magformer/models/magformer/arch.py:730-731`：`_inference_raw` 只取末层 `pred_logits/pred_masks`，**其余 8 组直接丢弃**。

也就是说：每个 query 的"9 帧解码轨迹"（cls 概率序列 + 512² 掩码序列）在当前推理链中**免费存在**。掩码画布 512²、逐层 `forward_prediction_heads`（multiscale_decoder.py:327-341）的输出分辨率与最终导出同源。

### a.3 为什么轨迹携带排序新信息（因果链）

训练侧的机制保证（全部为已验证事实，非假设）：

1. **9 个逐层头都被深度监督校准**：criterion 对 aux_outputs 逐层计损失（Mask2Former 标准深监督），每一层的 cls/掩码头都是"该层时刻这个 query 是否已决定"的校准读出；
2. **o2o + AIM 使 keeper query 的梯度史一致**：AIM 已把匹配边距拉到 2.43σ——被稳定持有的 query 每步吃同号正梯度 → 其 cls 逐层**早熟、单调上升**、掩码逐层**锚定收敛**；
3. **搭便车/背景 query 的激活是晚发的**：未被匹配的 query 只吃 eos 梯度，其"看起来像目标"的激活来自深层的特征共激活 → cls 轨迹**非单调、晚层突现**，掩码支撑区游走。

由此定义三个每 query 可靠性信号（CQTR 三信号的零成本版本，arXiv 2609.06581）：

- **S1 语义持续性** `P_cls`：末 4 层 cls 概率的稳定比 `mean(p_l)/max(p_l)`（单调升 → 1；突现/震荡 → <1）；
- **S2 空间收敛** `P_mask`：末 4 层掩码的逐层归一化 L1 失配（软图口径，见 a.5）与质心漂移的联合；
- **S3 跨尺度冲突** `P_scale`：第 6/7/8 层的 cross-attn 分别消费 stride-8/16/32 三尺度（`i % 3` 轮转，multiscale_decoder.py:289），恰好构成最后一个完整尺度周期——三个"同 query、不同主导尺度"的掩码两两一致性（取 min，冲突敏感）。**这是 CQTR 反事实尺度干预的本征零成本替身**（真正的输入重缩放干预需要第二次前向 ≈ +40ms，超预算，只留作离线诊断臂，不进部署）。

### a.4 排序改变的三个攻击面（按 R1 的 FP 结构精确定位）

1. **det 64-256 桶的 AUC = 0.490（随机）**（R1 §3）：当前分数在该桶对 TP/FP **零信息**，n=10,882、AP 0.1461。任何弱信息的新信号在此桶**严格无害且期望为正**——这是本提案最干净的攻击面；
2. **<64 桶的重复喷洒（14.05 det/命中 GT）**：由**几何去重**处理（D 组件，见下），不靠分数——直接规避 (b) 变体的死因；
3. **256-1024 桶 AUC 0.654、15.5% hard-FP >0.5**：成熟大目标轨迹天然稳定（P≈1），不会被压；晚发大 FP 会被 S1 惩罚。

### a.5 D 组件：只降不升的掩码簇去重（soft mask-NMS）

图内按复合分排序，若 det j 与更高位 det i 的掩码 IoU ≥ τ_ov（512² 画布或导出 RLE），则 `s_j ← s_j × λ`（λ=0.05）。它是 R1 oracle 去重（每 GT 留最高分，+0.26pt）的 GT-free 代理。**只降不升**的结构保证其最坏行为有界（不会把任何 FP 抬上来），与 R1"重复本身排在 keeper 之下、害在稀释分数统计"的判读一致。

### a.6 关于 maskness 解耦/尺度归一的诚实立场（不作为主提案）

小掩码 maskness 结构上限 0.95-0.96 vs 大目标 0.99（EVIDENCE §5）是真实的结构压分，但**任何桶级单调提升 maskness 权重的做法就是 (c) 家族**（−13.1 / oracle 版也 −2.9），已证伪且机理清楚：压分的不只是 TP，是整桶 80.5% 的 hard-FP。本提案中 maskness 尺度归一**只保留两处从属角色**：(i) 消融臂 C（预期 ≈0 或负，用于确认证伪迁移，非收益来源）；(ii) 复合公式内对 maskness 因子做无 GT 的分桶中位归一（100 张无标注图，CQTR 协议），仅为了不让 maskness 因子与 P 因子的相对权重被尺度混淆——排序改变仍来自 P 的每 query 粒度。

### a.7 与最小掩码的量化相容性

<32px² 目标在 512² 画布仅 2-3 cell，二值化 IoU 量化过粗（取值 {0, 1/3, 1/2, 1}）。因此 S2/S3 的主口径用**软图失配** `1 − ||p_l − p_{l+1}||₁ / (2·max(||p_l||₁, ||p_{l+1}||₁))`（尺度无关、亚 cell 敏感），二值 IoU 只作为较大掩码的辅助项。质心用软质量加权。这保证最小桶的信号不被画布量化抹平。

## (b) 与 set-prediction / 导出契约的兼容性

1. **set-prediction 语义：不动训练、不动匹配。** 匈牙利/AIM 匹配、损失、权重全部冻结；TRS 只读取导出时刻的解码器内部状态并改写 `score` 字段。更准确地说：o2o 训练的语义本就是"每目标一个 query 代表"，而当前导出物平均每命中 <64 GT 带 14.05 个 det——D 组件的簇去重**恢复**而非破坏 set-prediction 的导出契约。
2. **COCO 导出契约：** dets 的 masks/category_ids/每图数量（≤100）不变；`score` 仍是正向置信度，只改排序；maxDets=100 全程遵守（**不触碰已关闭的 topk-200 分支**；见 a.8 的微臂区分）。评估器语义（PR 曲线池化排序）不变。
3. **位等与确定性：** 全部信号是静态形状张量上的逐元素/归约运算（200×9 层 × 512²），无数据依赖控制流 → 可被 CUDA graph 捕获，eager 与 graph 位等——与 `gpu_postprocess.postprocess_tensors`（gpu_postprocess.py:156-226）的既有契约同构。落点：在 `forward_inference_decoder_outputs` 返回的 aux_outputs 上加一个 trajectory 归约器，在 `postprocess_tensors` 等价位置改融合公式。
4. **部署延迟契约：** +2~5ms（算式见 (d)），基线 ~150ms 量级内，红线 ≤+10ms。
5. **与 EMA：** 轨迹在 EMA 权重（best.pt model_state_dict，部署权重）上前向获得，与校准/验证同一份权重，无 raw/EMA 混用风险。

### a.8（归入 b 的合同说明）微臂 D：复合切割键 ≠ 已关闭的 topk-200 分支

微臂 D 把"200 query 取前 100"的切割键从 cls 换成复合分（**仍导出 100**）。与已关闭分支的区别：topk-200 实验是**多导出再按分截断**（+0.09，表明追加的低分 det 无增量）；复合切割键是**同样 100 个名额、换更优的占用者**——被 cls 切掉但轨迹高度可靠的小目标 query 可能入围。其上界被 topk200 的 +0.09 与 keeper 图内排名（<64 中位 49、23% ≥90；64-256 中位 85、36% ≥90，R1 §3）共同锚定在 **+0~0.2pt**，仅作从属微臂，且默认关闭（常量拟合时以其在标定分裂上是否 ≥+0.05 决定开关）。

## (c) 理论收益上界与依据

### c.1 硬上界（内部证据优先，外部文献只作存在性证明）

- **重排序组件（在现有导出集上）**：R1 §1 排序最优反事实 `a_plus_dedup_ranked` = **+1.33pt**（0.2925→0.3058，标准口径，112K EMA dets），召回锚 AR_s = +1.61pt。这是**任何只改排序的机制在当前 det 集上的硬上界**；当前模型已兑现 95.5%（R1 结论 1）。F1@128K 封存标准口径基线 ≈ 0.2987（0.2700 trainer + 2.87pt 稳定合同偏移，R1 §0），上界结构原样迁移：**重排序 ≤ +1.6pt**；
- **存在性组件（复合切割键）**：≤ +0.2pt（topk200 +0.09 锚定，校准报告 §2）；
- **合计硬上界 ≈ +1.6~1.8pt 标准口径 AP_s**（0.2987 → ≤0.317）。

### c.2 期望落地（分解到 R1 的 oracle 分解上）

R1 上界 +1.33 的构成：oracle 去重 +0.26 ＋ TP/FP 分离与 keeper 质量排序 +1.07。本提案的兑现路径：

| 组件 | oracle 锚 | 期望兑现 | 依据 |
|---|---|---|---|
| D：soft mask-NMS | +0.26 | +0.1~0.26 | 重复簇几何上高度重合；只降不升，下界≈0 |
| TRS：TP/FP 分离 + keeper 排序 | +1.07 | 20-50% → +0.2~0.55 | 主战场是 AUC=0.49 的 64-256 桶（弱信号即严格改善）；<64 桶 top 已双峰分明（TP 0.100 vs FP 0.063，AUC 0.753），TRS 在该桶以不倒退为主 |
| 微臂 D：复合切割 | ≤+0.2 | +0~0.2 | 见 a.8 |

**期望合计 +0.3~0.8pt 标准口径 AP_s**（配对差分下 trainer 口径增量同量级；AP_s 0.2700 → 0.273~0.278）。子桶期望：AP<64 0.0298→0.035~0.045（oracle 去重单该桶即 0.0437）；AP64-256 0.146→0.155+。

### c.3 外部锚的用法与折价

CQTR（arXiv 2609.06581；调研B §2.2/候选5）：9 个冻结检测器 × 3 数据集 APs +1.95~3.81、TinyPerson +3.85、仅 100 张无标注图校准。**本提案不引用其绝对值做收益预测**——CQTR 的收益对象是排序远未兑现的冻结检测器，而我们的模型已兑现排序上限的 95.5%；CQTR 在此仅证明两件事：(i) 解码轨迹信息在冻结检测器中真实存在且训练自由可变现；(ii) 无标注小样本校准协议可行。另按调研B §4.8 的证据分层提醒：CQTR 为单作者未评审新作——上界与折价全部由内部 R1 反事实锚定，不依赖该文成立。

### c.4 不做的事（防倒贴）

不做桶级提分（(c) 家族）、不做质量纯排序（(b) 家族）、不做 matched→1（(a) 家族）、不做 topk-200 导出与二值化阈值变更（实测关闭）、不做 NorCal/FRACAL 类先验方案（尺度尾 hard-FP 与 TP 同类同分布，无先验分离面，调研C §4.2）。

## (d) 开销预算

### d.1 推理延迟（部署形态，B=1，200 query，512² 画布，9 帧轨迹）

- **前向零增量**：9 组逐层预测今天已物化（a.2 代码事实），不新增任何层计算；
- **轨迹归约增量**：末 4 帧软图失配 + 末周期 3 帧两两一致性 + 质心/面积 ≈ 25-30 遍 52.4M 元素（200×512×512）的逐元素/归约 ≈ 1.3-1.6 GB 显存流量 → A100 级（~2TB/s）**约 1-2ms**；含 kernel launch 与 cls 轨迹（9×200×2，可忽略）保守计 **2-3ms**。若先按 cls 取前 160 再归约，再省 ~20%；
- **D 组件（soft mask-NMS）**：100×100 上三角 ≈ 4,950 对掩码 IoU，512² 画布 GPU 上 ≈ 1.3G 元素运算 ≈ **~1ms**（或在导出 RLE 上主机侧 ~2ms，二选一）；
- **合计 +2~5ms**（上限情形含全部微臂），远低于 +10ms 红线。融合公式本身是每 det 一次乘加，<0.01ms。
- 可选优化（不作为承诺）：把轨迹归约折进解码器循环内已有的 attention-mask sigmoid 遍历（同一张量已被动过），边际接近零。

### d.2 显存

**0 新增**：aux 张量在现推理中本已存活至 forward 返回（multiscale_decoder.py 的 `predictions_mask` 列表持有引用），轨迹归约在其被释放前消费。轨迹特征落盘仅 200×9×~12 float/图。

### d.3 训练/校准

- **零训练**：权重冻结，无梯度。允许的一次性离线常数拟合：{w1,w2,w3（P 三信号权重）, λ, τ_ov, κ, α} ≤ 7 个标量；
- 校准成本：1 次全 val 前向（3276 图，~1h GPU，与一次 eval 同量级，R1 §堵点2 的验证成本先例）+ 500 图分裂上网格搜索（500 图 COCOeval 秒级 × ~百组配置 ≈ 分钟级 CPU）。

## (e) 正确性验证方案（封存权重/dets 离线，判读数字前置）

资源（已核实存在）：`output/aps_20260913/p5_runs/f1_seal_128k/{best.pt(EMA model_state_dict), coco_instances_results.json}`、`magformer_datasets/20260318_1K_32254/annotations/instances_val.validated.json`。

### 阶段 0：基线与上界重锚（CPU，无前向，~小时级）

在 128K 封存 dets（235MB JSON，RLE 掩码内含）上复算标准 COCOeval（maxDets=100、同 R1 分桶）：
- 断言基线 = 0.8744 mAP / AP_s ≈ 0.2987（标准口径）——校准报告 §2 的协议闭环复现；
- 重跑 R1 反事实表的关键三行（`a_plus_dedup_ranked` / `dedup_fixed` / `a_separate`）在 128K dets 上的值，重锚本提案上界（预期 +1.2~1.6pt 区间）。若重锚上界 < +1.0pt，本提案自动降级为"仅 D 组件 + 微臂"并如实报告。

### 阶段 1：D 组件独立验证（CPU，无前向）

在封存 dets 上做 soft mask-NMS（RLE IoU，τ_ov 网格 {0.5,0.6,0.7} × λ {0.05,0.1}），只改 score 字段重评。
- **门：ΔAP_s ≥ +0.10pt 且 AP_m/AP_l ≥ −0.05pt。** 过门则 D 单独已是可部署件（+2ms 内）。

### 阶段 2：轨迹特征转储（GPU，1 次全 val 前向，~1h）

给 `forward_inference_decoder_outputs` 加钩子，从 aux_outputs + 末层输出转储每 query 轨迹特征（软失配链、末周期两两一致性、cls 稳定比、质心漂移、逐层面积/均值概率 ≈ 200×9×12 float/图，全 val ~200MB）。
- **闭环断言**：同次前向复写 dets JSON，其 mAP/AP_s 与封存值逐位一致（复刻校准报告 §2 的评估链闭环验证），从而轨迹特征与封存 dets 按 (image_id, 构造序) 严格对齐——不依赖 JSON 里不存在的 query 索引。

### 阶段 3：复合拟合与全量评估（CPU 为主）

- **拟合**：前 500 图分裂上网格搜索 ≤7 常数，目标 = 分裂上标准 AP_s（正则：限制 w 幅度，防过拟合）；同时跑无 GT 版（100 图中位/方差归一，CQTR 协议）作为纯度臂 E；
- **评估**（全 3276，标准协议）：主表 AP_s / AP_m / AP_l + <64 / 64-256 / 256-1k 子桶 AP；辅助表：det 桶 TP/FP AUC（基线 0.753 / 0.490 / 0.654）、matched 分数中位、每命中 <64 GT 的 distinct det 数（基线 14.05）；
- 消融臂：A 仅 TRS ｜ B = A+D ｜ C = B+maskness 桶归一（预期 ≈0/负，证伪确认用）｜ D' 复合切割键（预期 +0~0.2）｜ E 无 GT 校准版。

**判读门（进部署的实测门，供裁决书采用）**：

| 指标 | 通过条件 |
|---|---|
| ΔAP_s（全 val，标准口径，臂 B vs 基线） | **≥ +0.20pt** |
| ΔAP_s（不相交 2776 图 holdout） | ≥ +0.15pt（防 500 图泄漏过拟合） |
| AP_m / AP_l | 各 ≥ −0.10pt（大目标稳定轨迹不得被误降） |
| det 64-256 桶 AUC | 0.490 → ≥ 0.58（新信息存在的直接证据） |
| det <64 桶 AUC | 不得降 ≥ 0.02 |
| AP<64 子桶 | ≥ 0.035（oracle 去重单桶 0.0437 的下沿） |

**杀死条件**：臂 B ≤ 阶段 1 的 D 单独 +0.05pt 以内（轨迹无增量 → 负结果如实报告，保留 D 若过门）；或 AP_l/AP_m 退化 >0.10pt（降级误伤 → 停）。所有臂在轨迹转储之后**零额外 GPU 前向**（纯 JSON 分数改写 + COCOeval），总 GPU 消耗 ≈ 1 次全 val 前向。

## (f) 与其它场的叠加兼容性

| 场 | 交互 | 兼容性处置 |
|---|---|---|
| P3-a（边界监督）/ P3-c（退火） | 训练期掩码/动力学，导出端只消费结果 | 正交。掩码质量提升会同步抬高 S2 收敛基线——常数重拟合即可（100 图离线，无重训） |
| P3-b（小掩码表示/软导出） | 改 maskness 因子与画布/阈值 | 复合公式中 maskness 是显式槽位；轨迹信号是画布无关的归约（软失配口径对表示更换稳健）。臂 C 常数与 P3-b 联动重拟合 |
| P4-a（o2m 增供）/ P4-b（种子 query） | query 数量/身份扩展 | 轨迹数学逐 query、对 Nq 线性、无身份假设；切割键公式不变。种子 query 若有 warmup 导致轨迹更短/更陡，属可拟合的分布差异（w 重拟合）；P4-b 的"分数捆绑"成功后本场上界自然收窄——**P4-d 是零训练的"先变现存量"桥**（执行序：P4-d 最先，BRIEFS §执行顺序一致），其转储/评估 rig 直接复用为 P4-c 的"小桶 TP 分数中位"量具 |
| P4-c（MAL/分数成型） | cls 语义漂移（cls→质量） | 最强交互场：若 MAL 把分数训练成质量感知，R1 上界中 TRS 可兑现的份额缩小，P_cls 的语义也变。处置：阶段 3 的 AUC 表即探测器（P4-c 落地后重跑 AUC，<0.55 则 TRS 退役、D 组件保留——D 与分数语义无关）。两场不共享任何代码路径，无冲突 |

**叠加原则**：TRS+D 的全部常数是"权重外"的导出期配置——任何其它场胜出后，重拟合是一次 100~500 图离线作业，不需要动 P4-d 的机制本体。

## 风险与诚实话（供裁决）

1. **轨迹可能分不开 keeper vs 重复**（两者都在目标上）——本提案不指望它分：重复交由几何 D 组件，TRS 主攻 TP/FP 与 keeper 排序（AUC 0.49 的 64-256 桶）。R1 oracle 分解里这两块是可加的（+0.26 与 +1.07）；
2. **EMA 平滑可能压缩轨迹方差**（权重平均 → 逐层输出更平滑，P 分布向 1 集中）——若发生，臂 A 在阶段 3 即显形（AUC 不动），纸面成本之外只花 1h GPU；
3. **逐层掩码与 masked-attention 自指耦合**（每层注意力掩码由该 query 自己的上一层预测掩码派生，multiscale_decoder.py:334-340）：游走 query 会失去支撑区、收敛 query 自增强——这正是轨迹信息量的来源之一，但意味着信号部分是自证的，只有阶段 3 的 AUC 表能裁决其净信息量；
4. **CQTR 单作者未评审**（调研B §4.8）：所有收益主张以 R1 内部反事实为锚，CQTR 只承担"存在性证明"角色；
5. 本提案阶段未跑任何实验；除写入本文件外未做任何仓库改动。
