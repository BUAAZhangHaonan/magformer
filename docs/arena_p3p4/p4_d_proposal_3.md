# P4-d 提案 #3｜QTR-Export：解码层轨迹可靠性导出键（零训练重打分 + 统一切割键）

提案人 #3（独立，未参考其它提案）｜2026-09-20｜场：P4-d 导出与分数融合（零训练场）

---

## 0. 一句话主张与判读摘要

**机制**：把导出键从 `score = cls × maskness` 换成 `S = cls × maskness × T`，其中 T 是从**解码器逐层轨迹**（推理前向中已算出、当前被丢弃的 9 次 head 输出）提取的 per-query 可靠性因子：空间收敛 SC、跨尺度一致 CC、语义持续 SP（A 臂），以及多阈值掩码剖面特征（B 臂）。同一个 S 同时充当 top-100 切割键与导出分数。全部常量在封存权重上一次性离线拟合。

**判读**：
- 预期 AP_s **+0.2~0.4pt**（stretch +0.5），本场全部机制合计硬上限 **+0.6pt**（r1_score 反事实锚，见 §4）；AP_m/AP_l 守门跌幅 ≤0.1pt。
- 推理开销 **+0.3~1.0ms**（信号来自已物化的激活，算式见 §5），零训练。
- 一步 kill 门（V0，1 GPU 天）：轨迹信号在 <64 / 64-256 det 池的 TP-vs-hard-FP AUC 相对当前复合键提升 <0.05 → 机制证伪、止损。

## 1. 机制设计

### 1.1 现状：轨迹信号已经在算，只是被扔掉

代码事实（本仓库封存代码链）：
- `models/common/transformer/multiscale_decoder.py:824-1003`：解码器前向在**每个**层后都调用 `forward_prediction_heads`（为构造下一层注意力掩码所必需），产出 per-layer `outputs_class`（B,200,2）与 `outputs_mask`（B,200,512²画布）；含 layer-0 预解码头共 **9 次 head call**。`out["aux_outputs"]`（:1031-1038）在推理时同样返回，只是 `_inference_raw` 只消费最后一层。
- 每层 `F.interpolate(outputs_mask → level size)`（:1071-1072）已物化层尺寸（32²/64²/128²/256²）的 mask logits。
- 注意力层按 stride 32/16/8 循环、末层消费 stride-4（:859-867）——**层轨迹天然横跨 4 个尺度**。

因此"解码轨迹三信号"（CQTR 谱系）在我们的模型里不需要任何额外前向：只需在逐层 head 输出上挂一个 ~0.3ms 的池化旁路。

### 1.2 信号定义（全部 per-query，对 200 queries 全量计算，先于 topk 切割）

记 h_0..h_8 为 9 次 head call（h_8 = 最终层），c_l 为第 l 次的实类 sigmoid 分，m_l 为其掩码 logits 池化到 32² 网格后 sigmoid>0.5 的二值图（仅在有效像素区内）：

| 信号 | 定义 | 信息假设 |
|---|---|---|
| **SC 空间收敛** | {m_6,m_7,m_8}（对应 stride-8/32/4 条件下的三次预测）两两 IoU 的均值 | query 早早锁死在真目标上 → 掩码跨层稳定；hard-FP 假设游移 → IoU 低 |
| **CC 跨尺度冲突** | {m_4..m_8} 内两两 IoU 的最小值 | CQTR"跨尺度冲突"的单前向替身：层间注意力跨 stride 32→4，假假设在不同尺度条件间翻动 |
| **SP 语义持续** | min(c_6,c_7,c_8)/(c_8+ε) | 真 TP 的 cls 跨层饱和；FP 常是末层尖峰（min 拉低） |
| **B 臂：掩码剖面** | 从最终 1024² mask_probs（已物化）加算：面积比 A(0.35)/A(0.5)、A(0.7)/A(0.5)、峰值概率 p_max、核 maskness m(0.7核)/m(0.5) | 结构性压分的补偿不靠尺度常数（已证伪），而靠逐实例的剖面形状：连贯小掩码剖面陡、p_max 接近饱和；模糊 FP 剖面平 |

**组合器**（乘法形式，保持 S∈[0,1]）：

```
S = c_8^{w1} · maskness^{w2} · SC^{γ1} · CC^{γ2} · SP^{γ3} · Π profile_k^{δk}
```

- 主臂固定 w1=w2=1（即 T 只做乘性调制，不整体重标定 cls/maskness）；B 臂放开 w1∈[0.7,1.3]、w2∈[0,1.3] 扫描。
- 权重（≤10 个标量）一次性离线拟合（logistic on log-features，目标=校准切片上 matched-vs-hardFP 加权 AUC 偏向 <64/64-256 池，带 AP_m/AP_l 罚项）。
- **切割键统一**：topk-100 切割从 raw cls 换成 S_preview = c_8 · maskness32 · T（maskness32 为 32² 预览；h_8 的 512²→32² 池化是唯一新增插值）。被选中 100 条的导出分数用**与基线逐位相同**的 1024² 渲染链重算 maskness 后合成 S_final——掩码渲染链零改动。

### 1.3 明确不做（已关闭分支，不重开）

topk 100→200（实测 +0.09）、二值化阈值 0.45/0.40（≈0/负）、分位/桶级重标定（−13.1）、score=IoU（−11.9）、任何全局单调变换（AP 不变性）。也**不提案**尺度感知导出配额：切割侧全部存在性收益已被 topk200+按融合分截断实验定界在 ~+0.09，而 <64 det 池 80.5% 是 hard-FP，按 det 面积配额等于把 FP 定向抬进 top-100，预期为负——配额逻辑仅以"换切割键"的形式被本方案吸收。

## 2. (a) 机制因果链：为什么新信息能改排序而单调变换不能

1. **AP 对分数的全局单调变换不变**（Rank-DETR 立论；r1_score 变体 (c)/(c′) −13pt 的机理）。分桶单调映射同样是死路：(c″) oracle 只校准 matched 也 −2.9pt，因为 <64 池 80.5% hard-FP 与 TP 同类同分布，桶内抬分必搭车。
2. **本方案不是分数的函数**。SC/CC/SP/剖面是 per-instance 新随机变量：两条 det 即使 cls×maskness 完全相同，S 也可以不同——排序被轨迹证据改变。这就是"引入新信息改变排序"的合格性证明，且可证伪（V0 直接量条件 AUC）。
3. **为什么轨迹恰好对准残余错排**：r1_score 的反事实上界分解显示，当前排序已兑现重排上限的 95.5%，残余 +1.33pt 里 `a_separate`（TP 整体排到 FP 之上、组内保序）只值 **+0.52pt**——即"把 TP 与 FP 分开"这一信息本身在当前池上只值 0.5pt 量级。捕获它需要的是一个 TP/FP 判别器，而 cls 在 64-256 det 池的 AUC 只有 **0.490（随机）**、<64 池 0.753——存在明确的信息真空。轨迹信号的因果假设：**一个 query 若在 8 层解码、跨 4 个尺度的注意力条件下维持稳定的空间与语义假设，它是真目标的概率显著高于同分的抖动假设**。这与 CQTR（arXiv 2609.06581）"小目标知识在冻结模型里存在但欠激活"的判断同构，并与其"空间收敛/语义持续/跨尺度冲突"三信号一一对应。
4. **为什么 B 臂对准 maskness 结构性压分而不落入尺度归一陷阱**：小掩码几乎全是边界 → maskness 天花板 0.95-0.96（大目标 0.99，EVIDENCE §5）。按桶除以常数=变体(c)（死）。剖面特征（p_max、多阈值面积比）是**同一实例内部**的形状证据，不含任何桶先验：理想小掩码 p_max≈饱和、A(0.5)/A(0.35) 接近 1；出血/模糊 FP 剖面平缓——它给小掩码补的是"可达上限内的完成度"信息，而不是跨尺度抬分。

## 3. (b) 与 set-prediction / 导出契约的兼容性

- **一 query 一预测的集合语义不变**：不加 NMS、不做抑制；冗余假设只被降分沉底（与 r1_score 观察到的"当前排序已把 14.05 个重复压在 keeper 之下"结构同向）。近重复聚类去重（query_embeddings 余弦，`out` 里现成）仅作为 V1 的可选消融臂（oracle 上界仅 +0.26pt，默认关闭）。
- **评估器零改动**：仍导出每图恰好 topk=100、分数 ∈[0,1]、RLE 掩码；maxDets=100 语义不变，无需 `--truncate-to-max-dets` 类补丁。
- **掩码渲染链逐位不变**：masks 仍走 双线性×2 → 0.5 二值化；本方案只改"选哪 100 条 + 分数多少"。
- **确定性与图捕获**：全部新增算子静态 shape、无数据依赖控制流、无 host 同步（组合器留在 device 上，D2H 载荷不变）——`forward_inference_graphed`（arch.py:1200-1232）可继续捕获；eager 路径（arch.py:1485-1593）与 GPU 路径（gpu_postprocess.py:156-226 `postprocess_tensors`）行为一致。
- **部署无 GT 依赖**：推理期只用离线拟合的 ≤10 个标量常数。

## 4. (c) 理论收益上界与依据

**硬上限（本地反事实锚，r1_score report.md §1，112K EMA dets、R1 口径标准 COCOeval+自定义面积桶）**：

| 反事实 | AP_s 增量 | 对本方案的含义 |
|---|---|---|
| `a_separate`（完美 TP/FP 分离、保序） | **+0.52** | 噪声版 TP/FP 判别器的可寻址切片 |
| `dedup_fixed`（oracle 去重） | +0.26 | 可选臂，默认关 |
| `a_plus_dedup_ranked`（+oracle IoU 排序） | +1.33 | 需要 oracle IoU 知识，**不可达**，仅作全场重排上限 |
| AR_s 锚 | +1.61 | 同上 |
| 切割侧存在性（topk200 实测，校准报告 §二） | +0.09 | 换切割键的可寻址切片 |

→ **本方案可寻址上限 ≈ 0.52（分离）+ 0.09（切割）≈ +0.6pt AP_s**（R1 口径；其与 evaluate.py 口径存在 ~2.8pt 稳定加性偏移，增量近似可迁移）。捕获模型：Δ ≈ 0.52 × f，f = 复合键 AUC 相对当前键的分离缺口兑现率；若 V0 测得 <64 AUC 0.75→0.85、64-256 0.49→0.65（f≈0.25-0.45），对应 **+0.15~0.3pt**，加切割与去重残渣 → **预期 +0.2~0.4pt，stretch +0.5**。

**外部锚（折扣后）**：CQTR（query_existence.md 表 2.2 / 候选 5）在 9 个冻结检测器上 APs +1.95~3.81、TinyPerson +3.85、100 张无标注图校准、零训练。两点折扣：(i) 单作者 2026 新作未过评审（调研 §4.8 风险注记）；(ii) 其含**反事实尺度干预**（需额外前向）——我们不做：1024² 二次前向 ≈ +150ms、512² 降采样前向 ≈ +50ms，均 ≫ +10ms 红线，明确放弃，以层循环跨尺度轨迹（CC）作单前向替身，信号强度严格更弱。折扣后取其区间的下 1/3 作 upside 情景（与本地 +0.6pt 硬上限一致，取更紧者）。

## 5. (d) 开销预算

**零训练声明**：不更新任何模型权重；仅一次性离线拟合 ≤10 个标量（校准常数），属场规则明文允许项。校准与验证全部离线 GPU/CPU。

**推理增量（部署路径）算式**：

| 项 | 量 | 时间 |
|---|---|---|
| 旁路池化：8 次已物化 level 尺寸 logits（≤256²）+ h_8 的 512²→32² 一次 | 读 ≈ 200×(2·32²+3·64²+2·128²+256²)+200·512² ≈ 300MB @ ~1.5TB/s | ≈0.2ms |
| sigmoid+阈值+写 32² 轨迹缓冲（9×200×32² fp16/bool） | 3.7MB 写 + 逐层原地 | <0.05ms |
| IoU/SP/剖面约简（6-10 对 × 200q × 1024el；B 臂在已物化 100×1024² probs 上 3 次约简 ≈ 1.2GB 读） | 归约 | ≈0.1~0.4ms |
| 组合器 + topk（键替换，topk 本身成本不变） | 200×~10 flops | <0.01ms |
| **合计** | | **+0.3~1.0ms ≪ +10ms** |

无新增 D2H 传输、无新增 host 同步；显存 +≈8MB（轨迹缓冲）。CPU↔GPU 不越界（全场规则）。

## 6. (e) 正确性验证方案（封存权重/dets 离线，含 kill 门与判读数字）

**重要前提**：封存 `coco_instances_results.json` 只有切割后 top-100 的最终分数，**不含轨迹**——本方案必须一次重推理 dump（封存 best.pt 的 EMA `model_state_dict`，hook 旁路收集，权重只读）。校准链先例：全 val 3276 重推理 ~1h GPU。

- **V0 信号尸检（1 GPU 天，kill 门）**：dump 全 val 3276 的 per-query 特征（cls 轨迹 9×200、32² 轨迹掩码、canvas maskness/面积、B 臂剖面），按 r1_score 匹配协议（单类 max-segm-IoU≥0.5 = matched；IoU<0.3 = hard-FP）联结 GT。报告各信号及 logistic 复合在 det 面积桶 <64 / 64-256 / 256-1k 的 TP-vs-hard-FP AUC，对照组=当前键 cls 与 cls×maskness（cls 基线 0.753 / 0.490 / 0.654）。
  **门**：复合键相对 cls×maskness 基线 AUC 提升 ≥+0.05，且在 <64 或 64-256 至少一桶绝对 ≥0.60 → 进 V1；否则 **STOP**（诚实负结果，全场可复用：轨迹信号在本模型无效）。
- **V1 公式扫（CPU，dump 上纯后处理）**：主臂 γ 网格 + B 臂 w1/w2/δ + 可选去重臂。拟合只用前 1000 张 val（CQTR 用 100 张无标注；我们另报 train 侧切片作交叉核对），评估在 disjoint 2276 张与全 val 双口径。判读数字：evaluate.py 标准协议 **AP_s / AP_m / AP_l / mAP**（基线 0.2700 / — / — / 0.8744）+ R1 口径桶 AP（<64 0.0298、64-256 0.1461）+ TP 分数中位（<64 0.29、matched p50 0.613/0.723/0.821）+ hard-FP 分数中位漂移（通胀审计）。
  **ship 门**：全 val AP_s ≥ 0.2730（+0.3pt）且 AP_m/AP_l 跌幅 ≤0.1pt 且 mAP ≥ 0.8739。
- **V1b 端到端复核**：胜出配置走完整部署路径（新切割键 + 新分数）重推理全 val，与 dump 重打分结果逐位对账（差 ≤0.02pt），闭环防 dump/部署语义漂移（校准报告 §四 topk200 校验器事故的教训）。
- **V2 延迟**：与 ~150ms 基线同机微基准，门 ≤+10ms（预期 +≤1ms）。
- **V3 稳健性**：信号单因子消融（各 γ=0）、校准集尺寸敏感性（100/1000/全量）、EMA-vs-raw 权重上信号复算（EMA 平滑可能让轨迹过度饱和——若全 query SC≈1，即 V0 失败的一种形态，如实报告）。

**风险与对价**：最大风险是轨迹信号在成熟 EMA 权重上信息量不足（AUC≈基线）——V0 一天止损；次风险是常数过拟合 val——切片拟合+不相交评估+尺寸敏感性三重防护。

## 7. (f) 与其它场的叠加兼容性

- **P3-a（边界监督）/ P3-c（退火·EMA）**：纯训练侧，产出新权重后重跑一次 dump+拟合（流程 checkpoint 无关，~1 GPU 天/次）即恢复；掩码质量提升会同时抬高 maskness 与 SC，方向同向。
- **P3-b（表示/软掩码/面积自适应阈值）**：共享导出面。若面积自适应二值化胜出，maskness 定义改变 → B 臂剖面特征随之重定义（多阈值剖面天然兼容软输出），重拟合即可；实现合并点唯一（`postprocess_tensors` + 切割键），无结构冲突。
- **P4-a（o2m）/ P4-c（MAL·copy-paste）**：训练侧改变分数成熟度；组合器重拟合会自动降低轨迹权重（cls 变得更有信息量时 γ 收缩），退化路径平滑。
- **P4-b（种子 query）**：**正向协同**——种子 query 覆盖 92.1% 但 cls 0.22-0.29 导不出去；种子出生聚焦（probe 先验限定首层注意力）预期轨迹稳定性高，统一切割键正好从导出侧救低分种子，与 P4-b 训练侧形成"覆盖×导出"闭环。
- 唯一结构性依赖：解码器 ≥2 层且逐层 head 调用保留（当前架构天然满足；若未来砍层需重拟合，机制存活）。

## 9. 结论

P4-d 剩余杠杆里，唯一同时满足"零训练、≤+10ms、引入新信息"三要件的就是把**已被计算然后丢弃的解码轨迹**变成导出键的一等公民。本提案给出：合格性证明（非分数函数、非桶变换）、本地反事实硬上限（+0.6pt）与折后外部锚、+0.3~1.0ms 的预算算式、带一步 kill 门的离线验证协议。预期收益 +0.2~0.4pt AP_s——量级诚实地小，但这是该场全部剩余空间的现实定价，且验证成本仅 1-2 GPU 天、失败即干净止损。
