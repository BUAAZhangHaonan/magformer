# P3-a 提案 #2：BASS —— 边界锚定分层采样 + 覆盖率校准标签

**提案人**：独立提案人 #2（2026-09-21，斗兽场 P3-a「掩码边界监督」）
**一句话**：把 12544 点采样从「均匀候选池 + 双线性硬标签」改为「GT 边界带保底配额 + 池注入 + 链对齐覆盖率软标签」，三个改动全部落在 `_loss_masks` 一处，推理零开销。

## 0. 设计概览

| 子轴 | 组件 | 改动位置 |
|---|---|---|
| 点采样策略 | S1 边界带保底配额（每匹配 GT 每步 1568 点落入 coverage∈(0.05,0.95) 带，跨 8 个监督层复用同一坐标集） | `criterion.py::_loss_masks` |
| 点采样策略 | S2 候选池注入（带内候选并入 37632 均匀池再 topk-不确定性） | `criterion.py::get_uncertain_point_coords_with_randomness` |
| 损失形式 | L1 覆盖率校准标签（BCE/Dice 的目标从「1024 二值 GT 双线性」改为「GT 面积下采样到预测网格的 coverage 图双线性」，远场逐位等价、仅带内变软且与 CF1 oracle 定义对齐） | `criterion.py::_loss_masks` 标签源一行换 |

## (a) 机制因果链：为什么攻根因

**根因的精确定位——瓶颈在候选池，不在选择权重，也不在点总量。**

当前最终损失的采样（`criterion.py:89-112`）：每匹配 query 独立抽 `12544×3=37632` 个**均匀随机候选**（`torch.rand`，L97），按不确定性 `-|logit|` topk 选 9408 个 + 3136 个纯随机。重要性采样只能在**已抽到的候选里挑**。对 512² 画布上的 10px 目标（r≈5px）：

- ±1px 边界带面积 ≈ 63px² → **E[带内候选] = 37632 × 63/262144 ≈ 9.0 个/迭代**；含内部约 16 个（CPU 推算，与本场证据锚"每次迭代 ~4-47 个采样点"同量级吻合）；
- 即便 topk 把这 9 个全部保留，每次迭代喂给边界的监督点也只有 ~9-16 个，且位置逐迭代随机跳动。

由此推导出观测到的全部症状，链条闭合：

1. **边界梯度高方差 → 抖动**：per-mask Dice 估计在 n_fg≈16 个采样点上，相对标准差 ≈ √(0.25/16) ≈ **0.125**；BCE 的前景梯度集中在 ~16 个随机点上（balanced_ce 权重 99:1 只放大单点幅度，不降方差）。零均值高方差误差正是 ±1px 膨胀/侵蚀双侧都变差（<64: 0.652→0.476/0.256，R2 §D4）的签名，也解释 20× lr hires 组把噪声写在边界上。
2. **收敛到"稳定但错位"的边界脊**：ce/mask/dice 自 24K 统计平坦（SYNTHESIS P7）说明模型已在现有信号下收敛——现有信号对边界**无约束力**，收敛点就是抖动脊。高 IoU 段崩塌（AP@0.75=0.2465 / @0.90=0.0181，R2 §D1）是其度量后果；matched IoU 中位 0.635/0.674/0.737（<64/64-256/256-1k，R2 §D2）vs 链可达 frac≥0.75=0.817（R2 §D7）。
3. **标签不对齐度量**：即使点落上边界，BCE 目标是 1024 二值 GT 的双线性插值（`criterion.py:452`），其 0.5-等值线与「CF1 oracle = GT 穿生产链（1024→INTER_AREA→512 coverage→bilinear×2→0.5）」的 0.5-等值线在 2-3 cell 小目标上系统性不一致（<32px² 连 GT 穿链 frac≥0.5 都只有 0.443，R2 §D3）。我们是在为一个与打分器不同的目标函数做优化。
4. **跨层不一致监督**：7 个 aux + 1 个 final 共 8 次损失调用（`multiscale_decoder.py:1179-1183` + `criterion.forward:250-270`），每次独立重掷均匀采样——同一 GT 在 8 层收到 8 套互不一致的稀疏边界点，本身就是抖动源。

**BASS 的因果对应**：S1 把带内监督点从 ~9 个/迭代提升到 **1568 个保底点对 63px² 带的完全覆盖**（每带 cell 期望被采 24.9 次/迭代，P(cell 未被触到)=1.6e-11，CPU 推算）——Dice 估计相对标准差从 0.125 降到 ~0.018（n_fg≈800），方差降 ~50-100×；S2 让不确定性采样在带内有候选可选（纯均匀池下它"想选也没有"）；L1 把目标换成与 CF1 oracle 同一定义域表示的 coverage 图（oracle 不再是训练目标的平移）；跨层坐标复用消除 8 层间的采样不一致。**为什么不是只动损失形式**（Kervadec/Boundary-DoU/加权）：在 ~9-16 个带内点上再加权，权重≠信息，方差分毫未降——PointSup 的结论"点的位置比数量重要"（~10 点/目标≈全监督 94-98%，调研[8]）在本场的对偶是：**我们的点既不够也不在对的位置，且标签不是链要的形状**。纯头类方案（DCT-Mask AP_S 仅 +0.5、RefineMask 小目标仅 +1.5 vs 大目标 +6.0，调研[11][12]，反面教训 1）已证明救不了 <64 桶，必须 loss/标签侧先行。

## (b) 与二分匹配 / set-prediction 的兼容性

- 损失在 Hungarian 匹配**之后**、对每个 (query, GT) 匹配对独立计算；改点分布与标签源不产生任何跨 query 耦合、不分裂/合并 query、不改 o2o。set-prediction 语义（集合预测 + 一对一归属 + eos 类）逐条保留。
- 匹配器零改动：`matcher.py::forward` 的均匀 12544 点与 AIM 小 GT 列（`_aim_small_gt_costs`，L276-354）原样保留，AIM margin 2.43σ 的成果不承担风险；掩码变清晰只会二次提高其均匀列 SNR。
- 「匹配用均匀点、损失用分层点」的不对称在 M2F 原文即已存在（匹配均匀 vs 损失不确定性采样，且证明不掉点、省 3× 显存，调研[9]）——本提案只是把损失侧的采样分布再前进一步，同一安全论证沿用。
- `num_masks` 归一化、分布式 all_reduce、per-query 可加性均不变 → DDP 梯度语义与静态图假设不变。
- DN 路径（`_compute_dn_loss`）F1 未启用（`dn_enabled: false`）；若 P4-a 胜出启用 CDN，同一带注入工具函数可直接复用于其均匀采样（`criterion.py:680`），无结构冲突。
- 无塌缩模式引入：BCE+Dice 公式、5/20 权重、balanced_ce 全保留；Kervadec 单独使用塌成空掩码的教训（调研[1] 反面 3）不适用——我们的区域损失没有被替换，L2 加权臂默认关且 β 走 ramp。

## (c) 理论收益上界与依据

**硬上限**：CF1 反事实 +27.1pt（AP_s 0.2925→0.5636，检测集合与分数全冻结；R2 §D5 / SYNTHESIS 表一）——这是"掩码内容完美"的定义值。本提案的机制目标是其中「边界约束缺失 + 标签不对齐」份额：

1. **IoU 结构外推**：matched IoU 中位 0.635→0.817 的链可达差为 0.182（<64 桶）。若分层监督把中位推到 0.70-0.75（缺口关闭 35-65%），按 matched 分布平移近似，AP_s@0.75（现 0.2465）与 @0.90（0.0181）两个坍塌段是主要兑现场所（该段坍缩 87% 归掩码内容，R2 §D5）。
2. **文献锚（均注出处）**：医学小病灶距离图边界损失 +14.8pt DSC、HD95 减半（ISLES，调研[1]）；**M2F 系最贴近证据**：植物全景 M2F 仅加一个边界加权损失，小目标 PQ_weed +2.0、推理零开销（调研[21]）；PointSup ~10 点/目标≈94-98% 全监督（调研[8]，证明点位置密度是充分信号）。反面校准：精修头类小目标收益 +0.5~+1.5（调研[11][12]），故本提案不做头。
3. **声明的收益区间**：全训（128K 等长重训）机制份额回收 CF1 缺口的 1/4-1/3 → **+7~9pt**（与调研对候选 2 的保守折算一致，但本提案叠加了候选 2 没有的池-配额与标签对齐，取区间上沿）；**置信区间 +4~9pt**。8K/16K 短训门（从封存 128K 微调）预期净增 +1.5~4pt（短训只兑现一部分；判据对齐 Phase D 的 ≥+1.5pt 净增线）。
4. **为什么可信（超出文献的针对性论证）**：(i) 方差算术——带内点 9→1568、Dice 估计 std 0.125→0.018，直接打击"抖动非偏移"的病灶；(ii) 目标对齐算术——coverage 图就是 CF1 oracle 在 512 网格上的表示，训练目标与打分器 oracle 首次同构；(iii) 供给算术——<64 桶 rec@0.5 仅 12.2% 属 P4 域，但 64-256 桶 CF1 +18.7pt、256-1k +33.2pt（R2 §D5）的已检出目标全部立即受益（带配额对所有尺寸 GT 生效，带绝对宽度随 coverage 自动缩放，无固定 trimap 失真——调研[23] 反面 5 的规避）。

## (d) 开销预算

**训练 ms/it**（现 1440-1600 ms/it，红线 +20% ≈ +290 ms）：

- 每步一次性（跨 8 监督层复用）：coverage@512 + coverage@256 = 两次 `F.interpolate(mode="area")`，N≈55 GT → 读写 ≈ N×(1024²×1B + 512²×4B + 256²×4B) ≈ 190MB → @400GB/s ≈ **0.5 ms**；带掩码（2 次比较）+ 向量化 `torch.multinomial`（N×262144 类、有放回抽 1568+1568）≈ **1 ms**。
- 每损失调用 ×8：池扩容后的 grid_sample 增量（N×1568 点，μs 级）、topk 池从 37632→39200（不变阶）、逐点权重向量（N×12544 元素级）≈ 1-2 ms ×8 = **8-16 ms**；标签采样从 1024² 源换成 512²/256² 源，访存反而降 4×（中性偏正）。
- 合计 **+10~18 ms/it ≈ +0.7~1.2%**（红线 1/16）。若实现从简不做跨层复用（每层重算）最坏 +40~80 ms ≈ +3~5%，仍在红线内。
- 全部算子（area-interp / compare / multinomial / grid_sample / topk）CUDA 原生，GT 掩码本就在 GPU（`matcher.py:364`、`criterion.py:440`），**零新增 CPU↔GPU 传输**。

**推理**：**0 ms**。改动只在 `SetCriterion._loss_masks`（仅训练路径）；渲染链（`gpu_postprocess.py:200-210`、`arch.py:1546-1556`）、topk、maskness 打分、导出零触碰。

**显存**：新参数 0；新增持久 buffer 0；瞬态（no_grad，采样后即释放）：coverage N×512²×4B + N×256²×4B ≈ 55 GT 时 **~72 MB**（fp32；fp16 可减半；极端 100 GT → 131MB）+ 带掩码 bool ~14MB。峰值 +≤130MB，远低于 24GB/卡。

## (e) 正确性验证方案

**V0 CPU 单测（无 GPU，进 `tests/`）**
- T1 点密度：合成 10/15/30px GT → 断言带内点数 ≥1200/12544（基线 ≤47）；quota=0 时损失与基线**逐位一致**（回归守卫，防"顺手改了别的"）。
- T2 标签：远场（coverage∈{0,1} 区域）标签与基线 1024-双线性 |Δ|<1e-6；带内标签 ∈(0,1) 且沿穿界方向单调。
- T3 边界情况：0-GT 图、>100 GT 密集图、带 cell 数为 0 的 GT（回退均匀）、GT 触图像边。
- T4 机制微型验证：合成 2-3 cell 抖动目标上 10 步 GD，分层+coverage 的 IoU 轨迹快于基线采样（CPU 即可，验证"方差降→收敛快"的因果）。

**V1 冻结基座探针（~1 GPU·h，接线正确性）**：封存 F1 权重 + 新损失跑 500 张 val（不更新权重）：matched IoU/指标必须**严格不变**；产出诊断量——各桶带内点数、fg_ratio 位移（balanced_ce 将自动重归一化：10px 目标 fg_ratio 从 ~0.0003 升到 ~0.06，fg 权重 99→~15，损失幅值应保持 O(1)，若漂移 >2× 需调 `balanced_ce_min_fg_ratio`）、实测 ms/it 增量对照 (d)。

**G1 8K 短训门（裁决书主门，双臂）**：从封存 128K 起步，A 臂 = 原损失、B 臂 = BASS，同日程（镜像 R4 的 160K 余弦收尾，**必须双臂**以扣除退火尾段 +1.0~1.25pt 混淆）。判读数字（rescore 口径，R2 analyze2 B/CF1 协议）：
- 主判：matched IoU p50（<64）**0.635 → ≥0.70 过 / ≥0.75 强**；AP_s@0.75 **0.2465 → ≥0.30**；
- 次判：AP_s 净增（B−A）**≥ +1.5pt**；AP@0.90 ≥0.05；matched frac≥0.75（<64）0.242 → ≥0.35；
- 守卫（任一触发即回诊）：AP@0.5 跌幅 >1pt（软标签变糊）；maskness p50（<64）< 0.613（分数耦合恶化，P4-d 接口）；空掩码率上升（塌缩，调研[1]）；hires 组梯度范数比 >1.5×（P3-c 接口）。
- **G2 16K 延伸（可选）**：AP@0.90 ≥0.10 与 64-256 桶 matched IoU ≥0.75。
- 消融网格（lab 内）：`bass_band_quota ∈ {784, 1568, 3136}`、coverage 标签 on/off（分离采样与标签两子轴贡献）、β ∈ {0, 0.5}。

## (f) 与其它场胜出方案的叠加兼容性

- **P3-b（小掩码表示/解码）**：正交且协同——DCT-Mask/软导出是头与导出侧，本提案是损失侧；且 coverage 图可直接充当 DCT 回归分支的现成目标（第二阶段免再造标签）。
- **P3-c（训练动力学/退火）**：正交——它们消优化器侧噪声，我们加信号侧密度；G1 双臂设计已把退火收益扣除。唯一接口：边界梯度变密后需按守卫监控 hires 组（20× lr）梯度范数。
- **P4-a（匹配稳定性/CDN）**：AIM 未触碰；若 CDN 入场，`_compute_dn_loss` 的均匀采样可复用同一带注入工具（一个函数调用）。
- **P4-b（query 预算/种子）**：完全正交（query 侧 vs 损失侧），种子注入产出的新小目标 query 一旦被匹配即自动获得带监督。
- **P4-c（曝光/分数/copy-paste）**：乘法关系——copy-paste 增大小 GT 供给（0.85→更高可见数/步），每个新增小 GT 同时获得 ~50-100× 边界梯度密度，两方案收益相乘而非相加冲突；无损失项竞争（不同损失桶）。
- **P4-d（导出/重打分）**：零冲突（本提案推理 0ms）；校准后的 coverage 型掩码使带内概率分布更连续，maskness（二值掩码内均值概率）预期从 0.613 上移而非下移（现状错位导致大量 0.4 档概率滞留掩码内），对其 maskness-压分议题是缓解而非恶化——已列为 G1 守卫监控项。
