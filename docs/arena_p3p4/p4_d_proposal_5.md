# P4-d 提案 #5：TRE——解码轨迹重打分导出（Trajectory-Rescored Export）

提案人：#5（独立，未读同场其它 proposal）｜场：P4-d 导出与分数融合（零训练）｜日期：2026-09-20

**一句话**：导出排序键从 `cls₈×maskness` 换成 `锚定分 × 有界轨迹调制器`——用解码器前向**已经算出但被丢弃**的 9 个逐层预测（cls/box/mask 轨迹）构造 4 个尺度归一信号，在 topk 切割**之前**对全部 200 query 重排，改变"哪 100 个被导出"与"导出后如何排序"。新信息来自轨迹，不是 final 分数的函数，因此能改排序（单调变换不能）；前向、掩码、二值化全部不动，只动排序键。

## 0. 摘要卡

| 项 | 值 |
|---|---|
| 机制类别 | 重打分特征（CQTR 谱系，轨迹子集）+ maskness 尺度归一（子臂，预注册可能被砍）|
| 理论上界 | 排序侧 +1.3~1.6pt（r1_score 反事实实测锚）+ 存在性侧 ≤+0.1~0.3pt（topk200 锚），合计 ≈ **+1.4~1.7pt AP_s** |
| 预期兑现 | **+0.3~0.8pt AP_s**（标准协议，基线 0.2700），判决门 +0.3pt |
| 推理开销 | **+2~4ms**（全部 GPU，静态形状，CUDA-graph 可捕获）；显存 +0 |
| 训练开销 | **零**。仅离线拟合 ≤10 个标量常数（train split 上拟合，不碰 val）|
| 验证成本 | 全离线：约 6~8h GPU（2 次 dump 前向 + ≤4 次 evaluate.py 判决臂）|

## (a) 机制因果链：为什么轨迹信息能改排序，而单调变换不能

**形式论证**。AP 对每图 det 池化排序取 PR 曲线下面积，对分数的任意严格单调变换不变（maxDets 截断同序）。所以任何"分数的函数（含 det 面积条件化）"都先天无增益——r1_score 的实测正是这样死掉的：分位重标定 −13.1pt、score=IoU −11.9pt、matched-only oracle 校准 −2.9pt（r1_score §1 表）。**唯一有资格的机制必须引入 final 标量之外的新测量**。

**新信息在哪**。解码器前向本来就产出、且被推理链丢弃的逐层预测（`multiscale_decoder.py:824-1047`）：
- `predictions_class`：9 个点（layer-0 初始 + 8 层）× 200 query 的 cls logits；
- `predictions_boxes`：9 个点的逐层 box（`forward_prediction_heads` 里 `box_embed` 每层都算，`multiscale_decoder.py:1063`）；
- `predictions_mask`：9 个点、按 head_level 在 stride 8/16/32（末两层 stride-4）网格上交替渲染的逐层掩码。

它们作为 `aux_outputs` 随 `out` dict 一路返回到 `forward_inference_decoder_outputs`（`arch.py:1149-1161`），`_inference_raw` 只取最后一层（`arch.py:1493-1494`）。**读取它们零额外前向、零额外显存**（张量已在显存里）。

**因果故事（为什么轨迹分离 TP 与 hard-FP）**。set-prediction 解码器是迭代精化：真正"锁住"图像证据的 query 表现为 (i) 逐层 cls 单调上升（证据累积）；(ii) 逐层参考点/box 中心的位移方差相对目标尺度收敛；(iii) 跨层（跨 stride 8/16/32/4 网格）掩码形状稳定。hard-FP（杂波/纹理伪峰，与"喷洒式"重复 query）由注意力扩散驱动，逐层行为是振荡的。这正是 CQTR 在 9 个冻结检测器上验证的判断（APs +1.95~3.81，TinyPerson 最高 +3.85，零训练；query_existence.md §2.2 第 CQTR 行 / arXiv 2609.06581）。

**为什么它对我们特别对症**。我们的 FP 结构是"同类同分布"：det<64 桶 hard-FP 80.5%、TP/FP 分数 AUC 仅 0.75；**det 64-256 桶 AUC 0.49（随机）**（r1_score §3 表）。在 final 分数空间里这两个桶的 TP/FP 几乎不可分——判别轴必须来自别处，轨迹是现成的、免费的另一根轴。且我们的逐层 head_level 在 stride 8/16/32/4 间轮转（`multiscale_decoder.py:984`），**解码器本身就是一次内置多尺度集成**：跨层掩码一致性（信号 S3）直接读出这个集成的分歧度，等价于 CQTR"跨尺度冲突"信号的单前向版本（其原始版需尺度干预重前向，超我们 +10ms 预算，明确不采用）。

**四个信号（全部尺度归一，构造上不压小目标）**：

| 信号 | 定义（对每个 query，512² 画布/native 分辨率） | 新信息内容 |
|---|---|---|
| S1a/S1b 语义持续性 | p_l=sigmoid(cls_l)[obj]，l=1..9；S1a=p₉−p₁（净增益），S1b=上升步数/8（单调性） | final cls 相同的两个 det，层间历史可以完全不同 |
| S2 空间收敛 | c_l=逐层 box 中心；S2=std(c₁..c₉)/diag(box₉)（**以目标尺度归一的轨迹抖动**） | 这是 CQTR"尺度干预"精神的免前向版：几何量除以目标自身尺度，小目标不被惩罚 |
| S3 跨层掩码一致性 | m_l=0.5 二值化 aux mask_l；S3=mean_l IoU(m_l, m₉ 统一到 l 的尺寸) | 内置多尺度集成的分歧度；掩码出血/游移的 query 此处露馅 |
| S4 阈值稳定/边界锐度 | 在 final 512² 概率图上：A(0.6)/A(0.4)（0.4/0.5/0.6 三档面积比） | 概率分布的**形状**而非均值——maskness 只取均值，丢失的正是形状 |

**融合（有界调制器——直接内嵌 r1_score (a) 崩塌的教训）**：

```
anchor = cls₉ × maskness            # 现行 final 分数，原样
r = anchor × clip( 1 + β·(σ(w·S − b) − 0.5)·2,  0.7, 1.3 )
```

调制器有界 [0.7, 1.3]：排序以现行 anchor 为主干，轨迹只在 ±30% 内修正。r1_score §1 变体 (a)（matched→1.0，−14.85pt）证明"替换式重打分会把 14.05 个重复 det 抬到与 keeper 同层"；有界乘法调制器在构造上排除了这种灾难——重复 det 若在 anchor 上低于 keeper 超过 30%，无论轨迹多好都越不过去。参数 ≤10 个标量（w 4 维、b、β、g_min/g_max），离线拟合。

**topk 位置**。重排发生在 `postprocess_tensors` 的 topk 键上（`gpu_postprocess.py:184-185` / `arch.py:1539-1540`）：从"按 cls 切 100"改为"按 r 切 100"。这同时触及排序与存在性——被 cls 排在 101-200 但轨迹强的小目标 query 获得导出资格。这不是已关闭的 topk200 分支：topk200 只是把池子扩到 200 再按**同一** cls×maskness 排序截断（实测仅 +0.09，说明按旧键排序时边缘池无价值）；本提案换的是**排序键本身**。

**maskness 尺度归一子臂（A2，预注册低预期）**。EVIDENCE §5：理想小掩码 maskness 上限 0.95-0.96（stride-4）/ 0.85-0.9（stride-2）vs 大目标 0.99，TP 分中位 <64 桶 0.29 vs 大目标 0.80——`cls×maskness` 里有一个纯渲染物理的结构性压分。修正：`anchor' = cls × maskness/cap(√A)`，cap 为 log-面积上 3 结点分段线性（离线拟合常数），修正幅度有界 ×≤1.18。**诚实风险声明**：cap(A) 是 (score, area) 的函数，属于 r1_score 证伪家族；它与 (c) 的差别只在幅度（(c) 是把中位 0.06 拉到 0.8 的整分位搬运，本臂是 ≤18% 的乘法去偏）。是否成活由 G4 的桶内 AUC 判据裁决（hard-FP 与 TP 的 maskness/cap 比值若在桶内不可分，立即砍）。

**导出配额子臂（A3，仅作护栏）**。重排后若 top-100 中 det 面积 <256² 的数量低于护栏值，用 200 池中最好的小面积 det 补位。预注册判断：单独价值被 topk200 证据（+0.09）和"<64 池 80.5% hard-FP"近似封死为 ≈0±噪声；保留的唯一理由是防轨迹分自身带尺度偏置把小 det 挤出。G4b 若为负即删。

## (b) 与 set-prediction / 导出契约的兼容性

1. **不动集合预测本身**。query 集合、掩码 logits、二值化阈值（0.5）、双线性 ×2、maskness 计算全部原样；改变的只有 (i) topk 的排序键，(ii) 导出 det 携带的 score 标量。o2o 训练语义、AIM 匹配、推理链任何算子序列不变——这正是零训练场的定义域。
2. **导出契约逐项保持**：每图 ≤100 det、category 不变、掩码 RLE 与现行 bit-identical（选中的 query 其掩码走完全相同的 gather→upsample→sigmoid→threshold 序列）；score 仍为正浮点、量级与 anchor 同分布（有界调制保证）。evaluate.py 标准协议（全 val 3276、maxDets=100、按分数截断）无需任何改动。
3. **不做 NMS/去重**：r1_score 实测 oracle 去重仅 +0.26pt 且现行排序已把重复压在 keeper 之下；引入去重会引入 host 侧 IoU 矩阵与数据依赖控制流，破坏 CUDA-graph，收益为零——明确不做。
4. **CUDA-graph 兼容**：全部信号是静态形状（200 query、9 层、固定网格）上的纯 GPU 归约，无数据依赖控制流（配额臂若启用，需在 graph 外以固定槽位实现或放弃捕获——预注册：配额臂与 graph 二选一时弃配额）。可在 `forward_inference_graphed`（`arch.py:1200-1232`）内捕获。
5. **部署语义（分数含义漂移）**：score 的绝对含义变化会影响下游固定阈值用户。缓解：导出末端可加一条**纯单调分位回映射**（把 r 的分布映回 anchor 的分位）——单调变换不动 AP（本提案 (a) 的同一论证的反向使用），只恢复阈值语义。该步可选、零成本、离线可验证不变性。
6. **EMA 权重**：按校准报告结论 #2，一律使用 `p5_runs/f1_seal_128k/best.pt` 的 `model_state_dict`（EMA）；raw backup 仅作差分对照。

## (c) 理论收益上界与依据

**锚 1（排序侧硬上界，最关键）**：r1_score §1 反事实——在已导出 det 集上，"keeper 按 IoU 排序 + oracle 去重"（`a_plus_dedup_ranked`）也只到 +1.33pt（0.2925→0.3058），AR_s 锚 +1.61pt；base 已兑现自身集合上限的 95.5%。**任何不改变 det 集合的重打分不能超过 +1.3~1.6pt**。收益几乎全在小桶（该变体 <64 桶 0.0298→0.0486、64-256 0.1461→0.1725、256-1k 0.3697→0.3830）——与本场目标对齐。

**锚 2（存在性侧上界）**：topk200 实测 +0.09 AP_s（docs/2026-09-21-f1-128k-calibrated.md §二）——把池扩到 200 但仍按旧键排序时，边缘池增量价值 ≈0。轨迹键换键后对同一边缘池是**另一个选择器**，其额外价值受两处证据约束：R1 §3 显示 64-256 keeper 图内排名中位 85/100、36% ≥90（边界带拥挤，换键可双向换血）；但 <64 池 80.5% hard-FP（换进来的也多 是 FP）。诚实估计存在性侧 ≤+0.1~0.3pt。

**锚 3（机制存在性证明）**：CQTR 9 个冻结检测器 ×3 数据集全升，APs +1.95~3.81、TinyPerson +3.85（query_existence.md §2.2；arXiv 2609.06581）。注意两点折扣：(i) 其基线离各自排序上界远比我们近（我们已 95.5%），(ii) 其含尺度干预重前向，我们只用轨迹子集。CQTR 数字证明"轨迹携带 cls 之外的小目标判别信息"，不直接承诺我们的幅度。

**锚 4（可分性缺口=机会）**：det 64-256 桶 TP/hard-FP 分数 AUC 0.49（随机，r1_score §3）——新信号在这两个桶哪怕只做到 0.56-0.60，配合 +1.3pt 的排序天花板，兑现 +0.3~0.8pt 是保守推算（天花板 × 20-50% 捕获率）。

**汇总**：上界 ≈ **+1.4~1.7pt AP_s**（锚1+锚2，非简单相加，受 AR_s 锚封顶）；预期 **+0.3~0.8pt**；A2/A3 子臂各 ≤+0.1pt 且可能为负（预注册）。mAP 影响：大目标桶 anchor 排序几乎不动（调制有界且大目标轨迹普遍平稳），预期 |ΔmAP|≤0.1pt。

## (d) 开销预算

**推理增量（全部 GPU，逐项算式）**：
- S1/S2：9×200×(2+4) 个标量归约 ≈ 1.1×10⁴ 元素 → **<0.05ms**；
- S3：7 次 IoU：binarize + final mask 到各 aux 尺寸的双线性降采 + 展平点积 ≈ 7×200×(≤256²) ≈ 9.2×10⁷ int8/bool 元素 → **~0.5-1ms**；
- S4：0.4/0.5/0.6 三档阈值面积 ≈ 3×200×512² ≈ 1.6×10⁸ 元素归约 → **~1-1.5ms**；
- 复合分 + 200 上 topk：**<0.1ms**。
- 抵扣项：现行链路对 top-100 做 1024² 上采样+融合（≈1.05×10⁸ 像素）；新路径在 512² 上对 200 query 算信号（≈1.6×10⁸）后仍只对选中 100 上采样 1024²——净增像素级算力 ≈ 1.5×10⁸ 元素归约。
- **合计 +2~4ms**（基线 ~150ms 量级，目标 ~100ms），红线 +10ms 内裕量 ≥2.5×。
- **显存 +0**：aux 逐层张量本就在前向中分配并随 `out` 返回（§a），我们消费而非新分配。
- CUDA-graph：静态形状可捕获（§b.4）。

**零训练声明**：模型权重、损失、匹配、数据管线零改动。离线允许的唯一"拟合"是复合分 ≤10 个标量（w/b/β/界）与 A2 的 cap 3 结点——在 **train split**（20260318_1K_32254 的训练图，取 ~1000 张过封存模型 dump）上以 pairwise rank 目标（TP vs hard-FP，小桶加权）拟合；val 3276 全程只做判决，不参与拟合（防泄漏；CQTR 原文仅用 100 张无标注图校准，我们更保守）。

**验证期 GPU 预算**：dump val（标量信号 + 边缘池打包掩码）≈1.5h；dump train 1000 张 ≈15min；≤4 个判决臂各一次 evaluate.py 标准协议重推理（~1-1.5h/臂，r1_score 引 best.pt 全量重推理 ~1h 锚）。**合计 6~8h**，单卡。

## (e) 正确性验证方案（封存权重/dets 上全离线，预注册判读数字）

数据：封存 EMA（`p5_runs/f1_seal_128k/best.pt`）；GT `magformer_datasets/20260318_1K_32254/annotations/instances_val.validated.json`；基线 dets `p5_runs/f1_seal_128k/coco_instances_results.json`。基线（校准报告 §二）：**mAP 0.8744 / AP_s 0.2700 / AP_m 0.8655 / AP_l 0.9769**。

**Pass A（dump，val+train）**：hook 在 `forward_inference_decoder_outputs` 返回处，对每图全部 200 query 记录 S1a/S1b/S2/S3/S4/cls₉/maskness@512/area/box（每图 ~10KB）；另对 cls 排名 101-200 的 query 打包 512² 二值掩码（~3MB/图，共 ~10GB，供边缘池 IoU 标签）。
- **G0（协议闭环）**：dump 侧重放 top-100 导出，分数与封存 `coco_instances_results.json` 逐位一致（校准报告 §二对 raw/EMA 的同款闭环）。不过则 dump 管线有 bug，停止。

**G1（信号可分性门，最便宜的 kill switch，不跑 AP）**：在 val dump 上算 TP vs hard-FP（IoU<0.3）的 AUC，按 det 桶（r1_score §3 协议）：
- 64-256 桶：基线（cls×maskness）AUC 0.49 → **要求复合 r ≥ 0.56**；
- <64 桶：基线 0.75 → **要求 ≥ 0.79**；
- 两桶均不达标 → 机制死，不进入 AP 阶段（省下全部判决臂 GPU）。同时监控：每命中 GT 的 top 排名重复 det 数不得高于基线（防 (a) 式重复抬升）。

**G2（排序反事实，只改已导出 100 的分数）**：离线把 r 写回封存 dets（掩码不动），标准 COCOeval：
- 判读：ΔAP_s ≥ +0.10 继续放大权重；<0 则调制器退化为更窄界（0.85-1.15）再测一次。此臂同时是"轨迹 vs r1_score +1.33 天花板"的兑现率测量（预期兑现 20-40%）。

**G3（主判决：query 级重排换 topk 键）**：修改版 postprocess 按 r 取 top-100，evaluate.py 标准协议全 val 重推理：
- **通过门：AP_s ≥ 0.2730（+0.3pt）且 mAP ≥ 0.8734（−0.1 容差）**；
- 汇报 AP_s/AP_m/AP_l + r1_score 式自定义桶 AP（<64 / 64-256 / 256-1k）；桶 AP 为主要诊断（预期增益集中于两小桶）；
- 失败模式预注册：若 AP_s 升但任一小桶崩 + 大桶同步掉（(c) 签名），判为 FP 搭车，机制死。

**G4（子臂消融，各自单独跑）**：
- A2 cap 归一：先查桶内判据——<64 桶内 TP 与 hard-FP 的 maskness/cap 比值 AUC >0.55 才准进 AP；AP 判据 ΔAP_s ≥ +0.05 且无桶崩，否则删。
- A3 配额护栏：ΔAP_s ≥ 0 且无桶崩才保留为默认开关，否则删（预期大概率删）。
- 最优组合复跑一次确认可加性。

**产出物**：各臂 coco_metrics.json + 判读表落 `output/aps_20260913/arena_p3p4/p4_d/lab/`；在线实现落点为 `gpu_postprocess.py`（`postprocess_tensors` 增加可选轨迹入参）+ 新 `rescore.py`（信号与复合分，≤150 行）+ `arch.py:1597` `_inference_raw_gpu` 接线（graph 路径同构）。

## (f) 与其它场的叠加兼容性

| 场 | 改动性质 | 兼容性 |
|---|---|---|
| P3-a（边界监督）/ P3-c（退火） | 训练期损失/lr | 权重变了，机制不变：轨迹信号定义与解码器结构无关，只需在新权重上重拟合 ≤10 常数（离线 1h，零训练性质保持）。P3-c 若改 EMA 策略，与本提案无接触点。 |
| P3-b（掩码表示/软导出） | 掩码头/导出表示 | 若换 DCT/软掩码，S4 与 maskness/cap 常数需按新表示重拟合；S1-S3 与掩码表示正交。若 P3-b 也动导出融合公式，与 A2 二选一（G4 判据相同，可并入同一次消融）。 |
| P4-a（分组 o2m）/ P4-b（种子 query/预算） | 训练期支路（推理丢弃）/ query 出生 | P4-a 推理零痕迹，完全正交。P4-b 若 query 数扩容，轨迹信号 per-query 定义不变（静态形状随部署配置重捕获 graph）；若其热图头进推理端，与本提案信号独立可乘。种子 query 的"覆盖已解、分数卡 0.29"病灶正是本提案的变现对象——天然互补。 |
| P4-c（MAL/分数成型） | 训练期 cls 目标 | 最重叠的一场：MAL 改善 cls 的**校准与水平**，轨迹改善**排序的判别轴**——两者都作用于排序，收益预期次可加；若两场都胜出，需一次联合判决跑（复合分常数在新权重上重拟合后叠加，流程同 G3）。不冲突：MAL 不产生逐层轨迹信息。 |
| P4-d 场内 | 同场胜者若改融合公式/配额 | 本提案 anchor 项可配置（cls×maskness 或其替代）；A2 与任何"融合公式"类胜者是替代关系，由相同 G4 判据在同一 dump 上赛马，取优。 |

**叠加总原则**：本提案是导出端的纯后处理包装，对任何"新权重"都可零训练迁移（常数重拟合）；唯一资源冲突是各场都要 GPU 重推理，串行即可。

## 附：风险与诚实声明

1. **最大风险**：128K 的 cls 排序已兑现自身集合上限 95.5%（r1_score 结论 1），轨迹可撬动的只剩 +1.3~1.6pt 天花板的一部分——本提案从不宣称 CQTR 的 +1.95~3.81 可直接迁移，预期值压在 +0.3~0.8。
2. **A2/A3 子臂大概率被 G4 砍掉**（预注册），不影响主臂判决。
3. 拟合常数虽仅 ≤10 标量且在 train split 上拟合，仍存在 train→val 分布漂移风险；G1/G3 的双重门在 val 上把关。
4. 逐层轨迹信号的前提（aux_outputs 在推理前向中完整可用）已从 `multiscale_decoder.py:824-1047` 与 `arch.py:1149-1161` 代码核实；若未来某部署配置关闭 aux 计算（目前无此开关），需恢复其计算——增量约 7×200×mask_embed 投影，仍远小于 +10ms。
