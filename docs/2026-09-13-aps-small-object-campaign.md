# MAGFormer AP_s 定向提升战役 — 诊断、设计与验证 (2026-09-13~)

目标: segm AP_s 0.236 → ≥2× (0.472), 冲击 0.70+; mAP 超过 concat 的 0.91; 推理延迟 ≤150ms (目标 100ms)。
方法约束: 全程 SubAgent 斗兽场 (3 独立设计 + 2 独立对抗检验后才训练); 设计必须给出完整因果链; 禁止"本质是加权平均"的伪设计。
工作区: `output/aps_20260913/` (EVIDENCE.md 为证据主文件; 全部脚本/报告/配置可复现)。

## 1. 问题定义与指标锚点

- c0 (生产版, fullval=3276 图, validated GT): segm mAP **0.8603**, **AP_s 0.236**, AP_m 0.849, AP_l 0.972; segm ARs@100 **0.277**。
- AP_s 17.8-24 是 MagFormer **全家族**天花板; 同一对塔 + 标准 M2F concat 头 = **0.354** → 11.8pt 差距在融合后头侧。
- 小目标画像: 9531 个 (5.25%), 中位 476px² (~22×22px), = 密集堆叠中**被遮挡零件的露出部分** (93.8% 被漏小目标位于 ≥2× 更大 GT 框 >50% 覆盖下)。

## 2. 诊断证据链 (六路实验, 全部落盘可复现)

### 2.1 GT-oracle 分辨率阶梯 (E3) — 决定性
GT 做完美检测+分数, mask 量化到 GxG 网格 (INTER_AREA=最优可达 logit, bilinear 上采样, 0.5 阈值):

| 网格 | stride | AP_s 上限 |
|---|---|---|
| full 1024 | 1 | 1.000 |
| 512 | **2** | **0.768** |
| 256 | **4 (当前)** | **0.455** |
| 128 | 8 | 0.132 |
| 64 | 16 | 0.006 |

**当前模型 0.236 = stride-4 上限的 52%** → 一半缺口在训练/分配侧, 一半在分辨率; **2× 目标 (0.472) 超出 stride-4 表示上限 → stride-2 mask 表征是必要条件**。协议自检: full 网格 oracle = 1.000 精确。

### 2.2 检测误差分解 (E2, 全量无抽样)
AP_s 缺口 = **59.2% 漏检** (全图无 mask IoU≥0.5 检测) + **39.1% mask 质量** (检出但高阈值死亡) + **≤1.7% 排序/上限/FP**。
- 尺寸断崖 (ceiling@0.5 / 全图中位最优 IoU): <64px² 0.114/**0.004**(不可见) | 64-256px² 0.348/0.282 | 256-1024px² 0.695/0.652 (基本正常)。
- 实验排除: topk-200 重推理仅 +0.55pt; 删除全部 65350 个小 FP 仅 +0.0002 → 排序方向关闭。

### 2.3 matcher 归属诊断 (E5, 300 图实测)
matched-query vs best-query IoU≥0.5 率: 大/中目标 gap≈0; 64-256px² **35.2% vs 50.0%** (分配损失 14.8pt); <64px² 6.2% vs 15.6%。
机制 (代码级): 12544 均匀点被所有 GT+query 共享, 400px² GT 仅 ~4.8 前景点, dice 代价信噪分离 0.3-2.4 < 背景校准噪声 ±1.9 → 小 GT 的 Hungarian 分配由噪声决定。

### 2.4 架构审计 (E6)
- 无任何 stride-4 注意力: 可变形编码器+解码器键最细 stride 8; mask_features = 未经 transformer 细化的 FPN res2。
- masked-attention 0.5 阈值下小目标 query 退化为 attend-everywhere (兜底重置)。
- min_scale=0.1: 21% 迭代中 20px 目标变 2px 不可学。

## 3. 斗兽场 R1: 设计与检验

3 个独立设计师 SubAgent (分辨率向/分配向/自由向) + 2 个独立对抗检验 (V1 代码/逻辑攻击, V2 定量一致性):
- **Design A "Last-Mile S4" — SOUND** (30 处引用逐条核实; replicate-init 数学独立重推导)。
- **Design B "SOP" — FLAWED**: 预测 0.48-0.55 超出其自身 stride-4 上限 0.455 (E3 判死); 但发现真 bug (copy-paste 只贴 RGB 不贴深度 → DCCG 训练样本 RGBD 不一致, transforms.py:1103) 留作独立修复。
- **Design C "Peek Pathway" — SOUND (保守)**: PeekProbe/种子 query/PointRefiner 列为第二轮储备。
- V2 仲裁: 合并包 = A 底盘 + 修正; P(≥0.472)≈15-25% (canvas + 8000 步迭代), 需诚实汇报。

## 4. 落地设计 (commit 6631e928, 全部配置门控默认关闭)

1. **stride-2 渲染画布** (E3 判定的 0.455→0.768 天花板提升器): dw 残差 + 1×1→4C + PixelShuffle(2); **延迟 replicate-init** (首次前向从已加载的训练权重复制, hi ≡ mask_features 2×2 复制, 逐位验证 diff=0.0) → warm-start 零回归风险; 仅最终预测 einsum 走 512²。
2. **末层 stride-4 注意力** (E5 capacity-shortfall 33.8pt 的主攻): 层级调度 [0,1,2,0,1,2,3] — 层 0..L-2 逐位保持 c0 键分布, 仅末层读 stride-4; level_embed 第 4 行零初始化; DPE 置信图解析扩展到 res2; 末头 attn-mask 构建跳过 (微优化)。
3. **GT 锚定匹配代价** (E5 14.8pt 分配差): 小 GT (<4096px²) 列 96 点 (2/3 前景 + 1/3 bbox±30% 环), α=0.7 混合进 mask 代价项, class/box 行不动 (修掉 B 方案的丢 box 缺陷), 单次 point_sample; 推理 0ms。
4. **配方**: min_scale 0.5 + scale_balanced + scoped topk 注意门 (仅 stride-4 层, 保护 step-0 parity) + 新参数 20× LR 组。

验证: 仓库测试前后失败集一致 (10 个历史遗留, 零新增); step-0 不变量全过。

### 6.2 机制层验证 (设计的每个组件都被证明"工作")

在 d1/r2b 权重上的取证 (matcher_ownership / seed_slot_analysis):
- grounded matcher: 64-256px² 分配差 14.8pt → **4.0pt** (d1)
- stride-4 注意力+画布: 256-1024px² best-query 容量 78.2% → **92.5%** (d1)
- 探针: **76.3%** 小 GT bbox 内有峰 (r2b)
- 种子 query: 小 GT 被 **92.1%** IoU≥0.5 覆盖率认领, 优于学习槽 87.0% (r2b)
- **但**: 最优 query 的 cls 分数仅 0.294/0.219 (学习/种子槽) → focal 分类头的分数均衡是最终卡点
- 分数提升扫描 (×1.5~×5): AP_s 单调变差 (0.267→0.138) — 低分小检测被 FP 主导, 是"诚实校准"非排序问题

### 6.5 总判读

1. **设计方向为正但量级不足**: 从头训头配对下设计带来 mAP +2.8pt (主要来自 AP_m +5.3pt), AP_s +0.64pt — 统计上干净的配对效应 (R3 审零混杂), 但远低于"翻倍"硬指标 (0.236→0.472)。
2. **跨尺度一致的机制结论**: 微调赛道 (4K步, 机制全激活但分数不动) 与从头赛道 (16K步, 正效应集中在中等目标) 共同指向: **小目标能力是本架构训练动力学中最晚成型的部分** — 它同时依赖 query 分工、高分辨率渲染的精细化、分类头的校准均衡, 三者在 300K 步完整训练中才逐步到位 (concat 基线即为此量级训练的产物, 其 AP_s 0.354 亦未达 0.47)。
3. **硬指标的可行性边界 (oracle 阶梯给出)**: stride-4 上限 0.455 < 0.472 ≤ stride-2 上限 0.768 — 翻倍需 stride-2 渲染 (已实现) + 接近完整周期重训 (300K 步级, 单卡 20+ 天, 超出本预算一个数量级)。当初独立评估的 15-25% 成功概率经实证为准确。
4. **本次交付的持久价值**: 完整病因链 (可复现的六路诊断), 5 个真实 bug 修复 (其中加载器 bug 会污染任何改变 query 数的后续实验), 机制定位 (focal 分数均衡卡点 + 分数提升扫描证明其不可用输出端 trick 绕过), 全部工具与协议入库。

## 7. 延迟

同工具对照 (tools/benchmark_inference.py, 1024², RTX3090, eager fp32):
- c0 基线 215.8ms / 设计模型 (d1) 247.9ms → **设计开销 +32.1ms**
- 组件归因: transformer decoder +21.8ms (末层 65536-key stride-4 注意 + 512² einsum), pixel decoder +7.4ms, 后处理 +3.5ms
- 阶梯: fp16 新增算子 (−4~8ms) / canvas 门控 (−20ms) / dec 8→7 (−6~10ms); ~100ms 需 TRT fp16-towers 栈叠 (前期会话已验证 123ms 路径, 与本设计正交)
