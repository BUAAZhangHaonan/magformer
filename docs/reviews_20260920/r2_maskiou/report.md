## 结论摘要（全部 rescore 口径，segm AP_s=COCO small [.5:.95]）

1. 实测 AP_s=0.2925；反事实阶梯：给每个已匹配小目标换上"经精确生产链（512画布 area-interp → bilinear×2 → 0.5）渲染的 GT 掩码"→ **0.5636（+27.1pt）**；换成精确 GT 掩码 → **0.6033（+31.1pt）**；E3 完美检测+链 = 0.768。
2. 47.6pt 缺口（0.768−0.2925）分解：**掩码内容质量 27.1pt（57%）**、**检测集合/分数 16.5pt（35%）**（0.768−0.6033，掩码换到完美也不动）、**渲染链量化 4.0pt（8%）**（0.6033−0.5636）。
3. "掩码渲染/二值化/阈值机制"（链量化 4.0pt + 阈值自适应 +1.0~3.5pt）合计 **≈5~7.5pt，即缺口的 11~16%**——是真实但二阶的堵点；大头是 512 画布上 head 画的内容本身（painter，不是 brush）。
4. 高 IoU 坍缩归因：AP@0.5=0.604→AP[.5:.95]=0.2925 坍 31.1pt；换链完美掩码后同样坍缩只 4.0pt——**坍缩的 87% 是模型掩码质量，13% 是链量化**。
5. bbox 对照：small 桶 bbox@0.85=0.182 vs segm@0.85=0.066（+11.6pt）而 @0.5 反而 segm 高 2.8pt——掩码"能过 0.5 但到不了高 IoU"的模糊/边界抖动签名。
6. matched-pair（每 GT 分数最高且 IoU≥0.5 的 det）中位 IoU：<64 0.635（n=120/980，rec@0.5 仅 12.2%）、64-256 0.674、256-1k 0.737；frac≥0.75 仅 0.24/0.27/0.46。
7. AIM 对照：area<4096 的 per-GT 最优 det IoU 均值 = **0.767 vs AIM 实验室 frozen-c0 全 query 均值 0.4134**（口径差异见 §AIM）；<64 桶的无条件 ceiling 均值只有 **0.136、p50=0.006**——<64 的失败在检测集合，不在 IoU 阈值结构。
8. 渲染链模拟（GT 穿精确生产链）：<32px² 目标 frac(IoU≥0.5)@0.5阈值 仅 **0.443**，阈值降到 0.4 → 0.600（+15.7pt）；但按桶加权到全 small 桶，0.45/0.5 并列最优（链级 AP 估计 0.807/0.807 vs 0.4 的 0.798）——**统一降阈值总量近零，收益全在 <64 子桶（+7.5pt 桶内）**。
9. ±1px 形态学探针：生产 matched 小掩码膨胀/侵蚀都大幅变差（<64: 0.652→0.476/0.256）——边界误差是抖动/错位而非系统性偏小，**生产掩码上无免费的形态学/阈值红利**。
10. 代码核查：`object_mask_threshold: 0.7` 是**死配置键**（schema.py:307 定义，全源码零读取）；二值化 0.5 硬编码于 gpu_postprocess.py:210 与 arch.py:1555 两处。

## 详细分析

### D0. 前位脚本 bug 勘误（为什么旧 E 段全 0）

前位 `analyze.py` 的 D/E 段把 `cv2.resize(..., INTER_AREA)` 的结果再 `/4.0`。INTER_AREA 对 float 掩码做的是 2×2 **平均**（覆盖率 ∈[0,1]），再除 4 后最大值 0.25，任何 ≥0.3 的阈值产生空掩码 → E 段 oracle AP 全 0、D 段 "area" 行全 0。`analyze2.py` 已修正（不除 4），并用 E3 锚点自校验（见 D 段）。另修了本报告自己第一版 popweighted 权重 bug（每样本权 N_b 应为 N_b/n_b，影响聚合 4pt 级、不影响桶内阈值对比）。

### D1. 阈值曲线（A 段）："掩码化"损失随 IoU 阈值的变化

segm/bbox 各自跑全量 COCOeval（250s/229s），每桶 × 10 阈值。small(0-1024) 桶（d=segm−bbox）：

| thr | 0.50 | 0.55 | 0.60 | 0.65 | 0.70 | 0.75 | 0.80 | 0.85 | 0.90 | 0.95 | [.5:.95] |
|---|---|---|---|---|---|---|---|---|---|---|---|
| segm | .6036 | .5593 | .5043 | .4269 | .3399 | .2465 | .1502 | .0662 | .0181 | .0099 | .2925 |
| bbox | .5758 | .5245 | .4780 | .4273 | .3794 | .3255 | .2590 | .1825 | .0971 | .0249 | .3274 |
| d(segm−bbox) | **+2.8** | +3.5 | +2.6 | 0.0 | −4.0 | −7.9 | −10.9 | **−11.6** | −7.9 | −1.5 | −3.5 |

- @0.5 掩码反而**更容易**匹配（软掩码对小目标的 box 角部空白零容忍，掩码 IoU 相对宽松）；@0.65 起反转，@0.85 框比掩码多保住 11.6pt——**掩码内部/边界的模糊抖动在高 IoU 段单独把曲线打塌**，而目标的外接范围（bbox 由掩码导出）基本是对的。
- 分桶坍缩度（AP@0.5→[.5:.95] 相对损失）：all 10.4%、256-1k 50.3%、64-256 61.7%、<64 62.0%——目标越小坍得越狠，且 64-256 与 <64 已接近同样严重（掩码质量不再只欺负最小桶）。

### D2. matched-pair IoU 与 ceiling（B 段）

方法：每图 top-100 det（按分数）× 全部 GT 的 RLE IoU 矩阵；对每个 GT 取"segm IoU≥0.5 中分数最高"的 det（brief 口径），另记 per-GT max-IoU ceiling。26s 全量。

| 桶 | n_gt | matched(rec@0.5) | matched IoU p50/mean | frac≥0.75 | frac≥0.9 | score p50 | ceiling mean/p50 |
|---|---|---|---|---|---|---|---|
| <64 | 980 | 120 (12.2%) | 0.635 / 0.652 | 0.242 | 0.025 | 0.613 | **0.136 / 0.006** |
| 64-256 | 1,872 | 761 (40.7%) | 0.674 / 0.680 | 0.272 | 0.018 | 0.723 | 0.385 / 0.399 |
| 256-1k | 6,679 | 5,016 (75.1%) | 0.737 / 0.727 | 0.455 | 0.040 | 0.821 | 0.620 / 0.680 |

- <64 桶 matched 中位 0.635 与 AIM 实验室值 0.4134 **不可直接比**：matched 条件在 IoU≥0.5（中位数被下界顶起）；AIM 0.4134 是 area<4096 全体（含未命中）、全 query、无 0.5 下界的**均值**。可比口径见下。
- AIM 同口径对照（per-GT 最优 det IoU 均值，area<4096，n=41,605）：**0.767 vs AIM 0.4134 / oracle 0.4152**。注意三点差异：生产是 top-100 输出（子集，ceiling 只会被低估）、AIM 是 frozen c0 全 query、AIM 抽样 ≤16 GT/图。方向结论稳健：**新栈把 per-GT 掩码天花板翻倍（0.41→0.77）**，AIM 当年"assignment headroom 只有 1.1pt"的结论不可外推到 f1@112K。
- 但 <64 的无条件 ceiling 均值 0.136（p50=0.006，一半以上 <64 GT 的最优 det IoU<0.6%）与 c0 时代 0.004 几乎没动——**<64 是检测集合空洞，不是阈值结构问题**。

### D3. GT 渲染链模拟（D 段）：二值化阈值的可回收空间

方法：2,000 个小桶 GT（每子桶 cap 400/382），穿精确生产链：1024 →INTER_AREA→ 512（覆盖率，无 /4）→bilinear→ 1024 → {0.4,0.45,0.5,0.55} 二值化，逐掩码 IoU vs GT。

| 子桶(px²) | n | @0.5: p50 / frac≥0.5 / frac≥0.75 | @0.4: p50 / frac≥0.5 / frac≥0.75 |
|---|---|---|---|
| <32 | 400 | **0.400 / 0.443** / 0.165 | 0.583 / **0.600** / 0.258 |
| 32-64 | 382 | 0.793 / 0.866 / 0.592 | 0.798 / 0.955 / 0.675 |
| 64-128 | 400 | 0.841 / 0.960 / 0.770 | 0.838 / 0.988 / 0.833 |
| 128-256 | 400 | 0.888 / 0.995 / 0.863 | 0.871 / 0.998 / 0.940 |
| 256-1024 | 400 | 0.948 / 0.988 / 0.945 | 0.921 / 0.995 / 0.965 |
| <128 合并 | 1,182 | 0.752 / 0.755 / 0.508 | 0.784 / 0.846 / 0.587 |

- **<128px² 子群**：@0.5 frac≥0.5=0.755、frac≥0.75=0.508；降到 0.4 → 0.846/0.587（+9.1/+7.9pt）。**<32px²**：@0.5 连"IoU≥0.5"都只有 44%——0.5 面积多数决对 2-3 cell 目标系统性侵蚀，降阈值回收 15.7pt。
- 自校验：按桶人口（980/1872/6679）加权积分 frac 曲线得链级 AP_s 估计：0.4→0.798、**0.45→0.808、0.5→0.807**、0.55→0.757；与 E3 COCOeval 实测 0.768 同量级（frac 估计偏高 ~4pt，来自首图采样与 AP 近似，作锚不作物）。分桶自适应阈值 → 0.817（+1.0pt）、逐目标 oracle 阈值 → 0.842（+3.5pt）。<64 桶内自适应（选 0.4）0.371→0.446（**桶内 +7.5pt**）。
- 结论：**统一阈值几乎无聚合红利（0.45≈0.5），可回收空间集中在 <64 子桶且总量 +1~3.5pt**；真正的大头不在这。

### D4. ±1px 形态学探针（F 段）：生产掩码无系统性偏置

matched 对上 3×3 全结构膨胀/侵蚀各 1px（n=<64:120、64-256:761、256-1k:400）：

| 桶 | base | dilate1 | erode1 |
|---|---|---|---|
| <64 | 0.652 | 0.476 | 0.256 |
| 64-256 | 0.680 | 0.595 | 0.511 |
| 256-1k | 0.732 | 0.662 | 0.631 |

两个方向都显著变差 → 边界误差是**抖动/错位**（±1-2px 随机），不是整体偏小/偏大。含义：(i) 对生产掩码统一降二值化阈值（≈轻微膨胀）不会复现 D3 里链完美掩码的收益；(ii) 修复必须来自更好的内容（训练），不是后处理形态学。

### D5. 反事实 rescore（CF1/CF2）：掩码侧 vs 检测侧的精确切分

方法：score-greedy（COCO 式）匹配小 GT（<1024px²）→ 5,897 个 matched det；只替换这些 det 的 segmentation（分数、检测集合、其余掩码全部不动），全量 COCOeval。

| 量 | 实测 | CF1（链渲染 GT 掩码） | CF2（精确 GT 掩码） | E3（完美检测+链） |
|---|---|---|---|---|
| small AP[.5:.95] | 0.2925 | **0.5636** | **0.6033** | 0.768 |
| small AP@0.5 | 0.6036 | 0.6035 | 0.6036 | ~0.93* |
| <64 AP[.5:.95] | 0.0298 | 0.0566 | 0.0784 | — |
| 64-256 | 0.1461 | 0.3336 | 0.3817 | — |
| 256-1k | 0.3697 | 0.7013 | 0.7408 | — |

*由 D3 加权 frac≥0.5=0.932 估计。

- **CF1 曲线变平**：0.6035@0.5 → 0.6023@0.75 → 0.5267@0.90 → 0.3107@0.95。实测曲线 0.5→0.95 的 31.1pt 坍缩在链完美掩码下只剩 4.0pt（=CF2−CF1，纯链量化）。**高 IoU 段坍缩 87% 归掩码内容质量。**
- CF2 的 <64=0.0784 = 该桶 AP@0.5 原值（曲线完全平）：**<64 掩码侧已无任何可救**，全部卡在 rec@0.5=12.2% 的检测集合上。
- 64-256 桶 +18.7pt（CF1）、+23.6pt（CF2）；256-1k +33.2/+37.1pt——掩码质量损失最大的是 256-1k（matched 多），但相对损失最深的是 64-256。

### D6. 代码核查（mask_stride2_head / 二值化 / object_mask_threshold）

1. **stride-2 画布**：`models/common/pixel_decoder_msdeformattn.py:383-395` — `hires_dw`（3×3 depthwise，零初始化）作用在 stride-4 mask 特征上，`hires_proj`（1×1→4C，replicate 初始化自 `mask_features`，保证 step-0 与 c0 等价）+ `PixelShuffle(2)` → 512² `mask_features_hi`。仅在**最后一个 decoder 迭代**消费（`models/common/transformer/multiscale_decoder.py:986-996` `is_final_iter` 时替换 `final_mask_feats`）；此前层和 attention-mask 仍在 256 网格渲染。
2. **上采样+二值化**：`models/magformer/gpu_postprocess.py:200-210`（CUDA-graph 路径）与 `arch.py:1546-1556`（eager `_inference_raw` 路径，两处逐位一致）：`F.interpolate(..., mode="bilinear", align_corners=False)` 512→1024 → `sigmoid` → `mask_probs > 0.5`——**双线性、阈值 0.5 为硬编码字面量**（无配置出口）。打分 `final = cls × mean(mask_probs inside binary mask)`（maskness）。
3. **object_mask_threshold=0.7**：`config/schema.py:307`（默认 0.0，f1 config 写 0.7）——**全源码零读取**（唯一出现是 `tests/test_msmformer_recipe_alignment.py:31` 的 recipe 断言）。它是死键：既不进训练 query 选择也不进推理。对小目标的实际影响机制是上面硬编码的 maskness：小而模糊的掩码 binarize 后内部平均概率低 → 分数被压（B 段 score p50 0.613/0.723/0.821 随桶单调）。
4. 训练侧掩码监督（`models/common/criterion.py:423-500`）：point-sample（uncertainty+random）在 pred 网格上采点、GT 双线性取标签——最终层在 512² 网格监督，辅助层 256²。监督分辨率与画布一致；结合 D4，问题不是"没在 512 上监督"，而是学出来的内容在高 IoU 段不精确。

### D7. 归因汇总（"可画"条件的回答）

47.6pt 缺口（0.768−0.2925）：

| 成分 | pt | 依据 |
|---|---|---|
| 掩码内容质量（可画而没画好） | **27.1** | CF1−实测，检测集合/分数/其余掩码全冻结 |
| 检测集合+分数（<64 空洞为主） | **16.5** | E3−CF2，掩码完美化后仍剩的量 |
| 渲染链量化（512+bilinear+0.5） | **4.0** | CF2−CF1，同上冻结 |
| （链外：>512 画布才能拿的） | (23.2) | 1.0−0.768；<32px² 链不可画（D3） |

其中"渲染/二值化/阈值机制"再加阈值自适应 +1.0~3.5pt → **合计 ≈5~7.5pt（11~16%）**。画布（stride-2）作为"可画"条件已成立：链自身对 small 桶 frac≥0.5=0.932、frac≥0.75=0.817；当前模型只兑现了 AP_s 0.2925 / 链上限 0.768 的 38%。

**最便宜的验证动作**（按性价比）：
1. eval-time 二值化阈值扫描 0.45/0.40：`gpu_postprocess.py:210` + `arch.py:1555` 一处常数，跑一次 val 推理。预期聚合 +0~1pt、<64 桶内最多 +7.5pt（链级）；F 探针警告生产掩码或已偏大 → 可能 ≈0，但这是唯一零训练成本、直接检验"阈值机制 5~7.5pt"区间的实验。
2. 已完成零成本项：CF1/CF2（本报告）证明掩码侧上限 27.1pt、检测侧 16.5pt——任何后续训练臂的掩码/检测改进都可对照这两条线判读。
3. 若阈值扫描无效（预期内），把阈值机制从堵点表中降级，资源转向 #1（掩码内容质量训练侧）与 #2（检测集合，R1/R3 域）。

## AIM 覆盖度说明（掩码维度）

AIM 解决了什么：训练期小 GT 的 assignment 稳定性（margin 0.13σ→2.43σ，"列由噪声决定"的解药），为分数成型铺路——这是检测集合/分数侧（本报告堵点 #2）的使能器。它不消费推理时间、不改变渲染链。

AIM 未覆盖（本报告实测的残余）：
1. **推理链的渲染/二值化机制**（#3，5~7.5pt）：AIM 完全不触及 512→1024 bilinear、0.5 硬阈值、maskness 打分——这些在 matcher 之外。
2. **已检出目标的掩码内容质量**（#1，≤27.1pt）：AIM 改善"query 拿到好归属"，但 head 画出来的掩码仍只有 p50 0.635-0.737 / frac≥0.75 0.24-0.46；CF1 证明这与归属无关，是渲染头/监督问题。
3. **headroom 结论的时效性**：AIM 的"assignment 全部空间仅 1.1pt"是在 frozen c0、256 画布、全 query 口径（matched_iou 0.4043→oracle 0.4152）下测的。f1@112K 上同口径 per-GT ceiling 均值已达 0.767（area<4096）——掩码侧缺口（CF1 的 27.1pt）现在是最大单项，AIM 的杠杆落在其余 16.5pt 的检测/分数侧并为其提供稳定性前提。
