# R3 召回/查询容量/注意力门控 审阅报告

审阅人: R3 (独立) | 数据: 112K 步最新 eval (coco_instances_results.json, 2026-09-20 19:56, 247798 dets) + GT instances_val.validated.json (3276 图 / 181684 实例)
口径说明: 全文 AP/AP_s 用标准 COCO rescore 评估器 (复现 panel: segm mAP 0.8692 / AP_s 0.2925); trainer 内部口径 0.2638, 合同差异 +2.87pt 与 c0 时代 (0.2360↔0.2642) 一致, 所有对比同口径。

## 结论摘要（≤10 行）

1. **AP_s 缺口是召回主导**: 38.1% 的 small GT（<1024px²）在全图任何分数的 det 中都不存在 IoU≥0.5 命中；<64px² 桶 **87.8%** 从未被命中（best-IoU 中位 0.006）——该桶是"检测缺失"，不是精度/阈值问题。
2. AR_s (segm): @1=0.0, @10=0.0, @100=0.309 (vs AR_m 0.874 / AR_l 0.986)。小桶 PR 曲线在 IoU.5 下 precision≥0.9 保持到 recall≈0.62 后跳水为 0——精确卡在硬召回上限 0.619，高精度低召回形状。
3. **查询/检测槽容量不是硬约束**: 每图 small GT p50=1 / p90=12 / max=26 ≪ 200 queries；密集图 (small≥20) 仅 52 图、载 12.1% 小 GT，其 AP_s 0.229 vs 稀疏 0.302，加权到全局只差 ~0.9pt；稀疏图 AR_s 也仅 0.319——容量富余时召回同样低。
4. **去重/摊薄为零**: 每个 small GT 平均 1.30 个 det（≥2 个的仅 11.7%），oracle 每-GT留最优 det 后 AP_s 0.2925→0.2900 (−0.25pt)。
5. **AIM 面积单位无缺口**: 4096 是 1024² 画布 px²（matcher tgt_masks 即画布分辨率）；任何增广 scale≤2 下 COCO-small (orig<1024) 的画布面积 ≤4096，全部落在 AIM 网内。
6. **AIM 真缺口是 `sel[:16]` 截断**: val 740/3276 图的小 GT 超 16 个 → **4849/9531 (50.9%) 的 COCO-small GT 每次匹配都拿不到 AIM**（<64 桶 456/980）；train scale=1 时 33815/69013 (49.0%)，含尺度增广平均 36.7%——这些列回落到 AIM 要替换的噪声均匀列。
7. **topk 门控不饿死极小目标但只覆盖最后 1 层**: K=max(64, 2×预测面积)，在 256² 网格上 64 cell 是 12px 目标 (9 cell) 的 7.1 倍、8px 目标 (4 cell) 的 16 倍，且 per-query 无竞争 → min64 足够；但该门控 mask 仅被**最终第 8 层** cross-attention 消费，前 7 层 key 是 stride 32/16/8 网格 + 硬 0.5 阈值（原 attend-everywhere 病理仍在）。
8. 召回补全 oracle: 给 3634 个 never-hit 小 GT 注入自身 mask，score 0.99 → AP_s **+37.5pt** (0.667)；score 0.45（现实小目标分数水平）→ 仅 **+6.7pt**。召回缺失的物理空间巨大，但变现率被分数/排序门 (AR_s@10=0) 扣住。
9. 缺口归因 (0.768−0.2925=47.6pt): 召回维度 +6.7~+37.5pt（取决于分数流修复），容量 ~0.9pt，去重 ~0pt，其余 ~10.1pt 属已检出者的 mask 质量/分数（A=0.667 → 天花板 0.768 的残差）。
10. 欠收敛仍在贡献: 内部口径 AP_s 72K→112K = 0.2529→0.2638（最近 8K 窗 +0.03pt，减速中）。

## 详细分析

### D1 召回结构（必做 1）

方法: 全量 3276 图, 每个 small GT 计算 best-IoU over 该图**全部** det（不限分数、不做独占分配, pycocotools RLE IoU, C 实现）; AR 用 COCOeval segm maxDets=[1,10,100] 单趟; PR 曲线取 precision 数组 (IoU=.5, area=small, md100)。

| 子桶 (px²) | n | never-hit@0.5 | never-hit@0.3 | best-IoU 中位 | best-IoU p90 | 命中者 top1 score 中位 |
|---|---|---|---|---|---|---|
| <32 | 598 | **92.0%** | 85.1% | 0.001 | 0.426 | 0.16 |
| <64 | 980 | **87.8%** | 80.0% | 0.006 | 0.547 | 0.29 |
| 64-256 | 1872 | 59.3% | 42.9% | 0.399 | 0.769 | 0.63 |
| 256-1024 | 6679 | 24.9% | 11.6% | 0.680 | 0.856 | 0.80 |
| 全 small | 9531 | 38.1% | 24.8% | 0.615 | 0.843 | 0.78 |

- 疑点裁决: **<64px 桶 (panel 0.11) 是召回受限**——87.8% 的 GT 连一个 IoU≥0.5 的 det 都没有 (中位 best-IoU 0.006, 基本不可见); 阈值降到 0.3 也只多找 7.8pt。不是阈值/精度问题。
- AR (segm, 全类): @1 0.018 / @10 0.177 / @100 0.879。AR_s: @1 **0.0**, @10 **0.0**, @100 0.309——任何图的小 GT TP 都进不了前 10 检测。
- PR 形状 (IoU=.5, small): precision 从 1.0 缓降到 recall 0.60 处 0.897, 随即断崖为 0——饱和点 0.60-0.62 与硬召回 1−0.381=0.619 精确吻合 (交叉验证)。AP50_small=0.604。即: 已检出的小目标排得进去且精度高, 缺的是检出本身。

### D2 容量核算（必做 2）

每图 small GT (<1024px²): mean 2.91 / p50 1 / p90 12 / p99 21 / **max 26**; 含 ≥1 小 GT 的图 1859/3276。AIM 资格线 (<4096px²): mean 12.7 / p90 41 / max 55。
对照: 每图 det mean 75.6 / p90 100 (613 图打满 100 帽); 每图全部 GT mean 55.5 / p90 99 / max 100。

- 密集子集 (small≥20, 52 图, 1149 小 GT=12.1%): AP_s 0.2288, AR_s@100 0.2345; 稀疏 (1..19, 1807 图, 83.8% 小 GT): AP_s 0.3016, AR_s 0.3187。
- 判定: **查询/槽容量不是小目标召回的硬约束**。最直接的反证是稀疏图——小 GT ≤19、查询与 det 槽远超需求, AR_s 仍只有 0.319。密集效应加权到全局 ~0.9pt (0.121×(0.229−0.302)); E4a 的 maxDets 200 实测 +0.55pt 同量级。100-det 帽只在全目标维度偶发 binding (GT p90=99), 对小目标维度 (max 26) 从不 binding。

### D3 重复与摊销（必做 3）

- 每 small GT 的 det 数 (IoU≥0.5 且 score>0.05): mean 1.30 / p90 2 / 零 det 38.1% / ≥2 det 仅 11.7% (极值 69 是个别病态图)。
- Oracle 去重 (每命中 small GT 只留最高分 det, 删 8839/247798): AP_s 0.2925→**0.2900 (−0.25pt)**, AP 不动。重复 det 在高 IoU 阈值偶有贡献, 删了略亏。
- 重复簇 (box-IoU≥0.5, score>0.05): 簇均值 1.21, p90=1, 8.2% 簇≥2, 21.5% 的 det 有重复重叠——总体温和, 无"高响应查询坍缩到同一目标"的迹象; 200 query 池的产出 (75.6 det/图 vs 55.5 GT/图, 1.36×) 不构成对小目标的槽挤占 (与 c0 误差分解 (d) FP 挤占 0.02% 一致)。

### D4 topk 门控代码核查（必做 4）

实现 (`multiscale_decoder.py:1086-1154`): 每 query 对其**自身**预测 mask 的 sigmoid 概率图取 top-K cell 为 attended (mask=False), K = clamp(pred_area×2.0, min=64), pred_area 为 256² 网格上 sigmoid>0.5 的 cell 数; 无 RNG。

层调度 (dec_layers=8, `hires_final_level`): level 顺序 = [stride32, stride16, stride8, stride4] (pixel decoder: deformable res5/4/3 逆序 + FPN res2)。layer i 的 key level = 3 (仅 i=7) 否则 i%3; 注意力 mask 来自上一次 head call, 其渲染 level = 3 (i≥6) 否则 (i+1)%3。因此:
- **topk 门控 mask (256², min64/ratio2) 只被第 8 层 (最终层) 的 cross-attention 消费一次**; layer 6 自身的 cross-attn 消费的是 i=5 渲染的 stride-32 mask。
- layer 0-6 的 key 网格 = 32²/64²/128² 循环, 掩码用硬 0.5 阈值——audit #2 的小目标退化 (低置信 query 全 mask / attend-everywhere) 在这 7 层原样保留。

几何推算: 12px 目标在 stride-4 = 3×3=9 cell (144px²), K=max(64,18)=64 → 门控窗口是目标的 **7.1 倍**; 8px 目标 4 cell, K=64 = **16 倍**; min-64 只对 <18px 目标 binding。64/65536=0.098% 网格。per-query 独立取 top-K, 无跨 query 竞争 → **按数量不饿死极小目标**; "选中概率"不适用 (非 anchor 选择, 位置完全由 query 自己的 mask logits 决定)——门控是稳定器不是发现器: 无信号 query 的 top-64 落在它误指向的大目标上, 与 0.5 阈值同样无法把注意力引向小目标。真正的残余是覆盖面: 小目标 query 的获得/持有发生在 layer 0-6 (无门控、粗网格、亚 cell), 只有最后 1 层享受 256² 门控。

### D5 AIM 生产化核查（必做 5, 重点）

触发链 (`matcher.py:404-416` → `_aim_small_gt_costs:268-332`): `areas = tgt_masks 求和`, `sel = (areas<4096)&(areas>0)`, **`sel = sel[:16]`**, blend `C + 0.7×(aim − uniform)`。

- **单位**: tgt_masks 是 dataset 输出的 1024² 画布掩码 (`data/dataset.py::_build_instances`, image_size 1024, 无额外下采样; trainer `_prepare_targets` 只搬设备)。故 4096 = 画布 px² = 原图 px² × s² (s=ResizeScale 采样于 [0.5,2.0])。s=1 时两者相等。
- **<64px 桶是否全覆盖**: 面积维度全覆盖——COCO-small (orig<1024) 在任何 s≤2 下画布面积 <4096 (s=2 时 1024×4=4096 恰为边界, 测度零), 1px GT 亦有单测。**缝隙在数量维度**: `sel[:16]`。
- **量化** (val, s=1, 标注顺序=matcher 顺序): 740/3276 图的 <4096 GT 超 16 个; 17686/41605 (42.5%) 的 <4096 GT 出帽; 其中 **COCO-small 4849/9531 (50.9%)**、<64 桶 456/980 (46.5%)、<32 桶 261/598 (43.6%) 每次 matcher 调用都拿不到 AIM。train (25654 图): 5273 图超帽, scale=1 下 33815/69013 (49.0%) small GT 无 AIM; 对 16 点 scale 网格平均 (0.5→阈值等效 16384 orig px², 2.0→1024 px²; 未建模 s>1 裁剪丢 GT, 故为上界) **36.7%**。
- 后果链: 出帽小 GT 的 mask cost 列 = 均匀 12544 点估计 (400px² GT 仅 ~4.8 前景点, SNR 噪声主导) → Hungarian 归属掷硬币 (margin 0.13σ) → 深监督 ×9 每层重掷 → 分数无法成型。AIM 花钱解决的正是这个, 但对一半目标没生效; 且增广使"哪些 GT 出帽"逐样本变化, 归属不稳定性反而被增广注入。另注意 α=0.7 混合使 AIM 列仍含 30% 噪声均匀列 (次要残余)。
- 一并记录: `cost_bbox=5.0 / cost_giou=2.0` 混合行不受 AIM 影响 (设计如此); matcher 对 final (512²) 与 aux (256²) pred_mask 均用归一化坐标点采样, 分辨率无关, 面积阈值始终取自 1024² tgt_masks——一致无歧义。

### D6 缺口归因（必做 6）

天花板锚: 0.768 (E3 stride-2 GT-oracle, 同 rescore 评估器; F1 有 stride-2 终头适用)。缺口 = 0.768 − 0.2925 = 47.6pt。

Oracle 阶梯 (本报告实测, segm rescore):

| 变体 | AP_s | Δ | 含义 |
|---|---|---|---|
| baseline | 0.2925 | — | 现状 |
| +3634 never-hit 小 GT 注入自身 mask @0.45 | 0.3595 | **+6.7** | 现实分数水平下召回补全的变现 |
| 同上 @0.99 | 0.6673 | **+37.5** | 召回补全的物理上限 (顶部排序) |
| 全部 9531 小 GT 注入 @0.99 (全分辨率) | 0.9901 | +69.8 | 总上限 (不受 stride-2 量化约束) |

归因区间:
- **召回维度 (检出缺失): +6.7 ~ +37.5pt** (= 缺口的 14%~79%)。下界是当前分数校准下的变现, 上界是分数流修复后的变现; 建议中枢 ~20-30pt。它的两个根因按本报告证据排序: (i) AIM 截断使半数小 GT 归属不稳 (D5); (ii) 前 7 层粗网格+硬阈值注意力使 query 无法在获得层定位亚 cell 目标 (D4)。
- **容量维度: ~0.9pt** (≤2%): 密集子集差加权; maxDets 加倍历史 +0.55pt。
- **去重维度: ~0pt** (oracle 略负 −0.25pt)。
- **残差 ~10.1pt** (0.667→0.768): 已检出小 GT 的 mask 质量 (高 IoU 阈值) + 排序细节——属 mask 表征/分数域 (R1/R2), 非本审阅维度。
- 另有欠收敛分量: 72K→112K 内部 +1.1pt 且减速, 128K 停机点未饱和但边际小。

## AIM 覆盖度说明（召回/容量维度 AIM 解决了什么 / 残余什么）

**解决了什么 (设计域内)**: 面积单位无缺口——4096 画布 px² 在全部增广尺度下覆盖 COCO-small 全体含 <64 桶 (D5); 统计量尺度无关 + 确定性窗口使**拿到 AIM 的那一半**小 GT 列的 margin 从 0.13σ → 2.43σ (实验室), 这是分数成型的前提条件; 推理零开销。容量维度 AIM 无关 (matcher 不消耗查询容量), 召回维度它是归属稳定器——本报告的 AR_s@100=0.309 与 P3 分数成型证据 (<64 TP 分数中位 0.29, 相比 s0c 时代已显著改善) 与"AIM 覆盖的那半受益"相容。

**残余什么 (本审阅的新发现)**:
1. **数量截断 `sel[:16]`**: 50.9% val / 49.0% train (scale=1) / 36.7% (增广均值) 的 COCO-small GT 完全拿不到 AIM——它们正是均匀点噪声最极端的人群 (<64 桶 46.5% 出帽)。AIM 的实测收益 (matched-IoU 0.4134) 是在实验室 n=754 记录、每图小 GT 远少于 16 的分布上测的, 生产分布下其有效覆盖减半; VERDICT 的 +0.3~0.8pt 估算应按此打折, 修复截断后才是全额。
2. **α=0.7 混合残余**: AIM 列保留 30% 噪声均匀列 (次要)。
3. AIM 只修 matcher 归属, 不修 (a) 前 7 层注意力门控缺失 (D4)、(b) 分数/排序门 (D2 的 AR_s@10=0)——召回缺口的主要变现路径仍被 (b) 扣住, 这是跨 R2 的接口。

修复优先级建议: 截断修复 (阈值降到 1024px² 或分块向量化) 是本报告发现的唯一"一行级"高确定性 AIM 缺陷; 与门控扩层、分数流三者叠加才可能把召回维度的 6.7pt 现实变现推向 37.5pt 上限。
