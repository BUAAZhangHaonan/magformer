审阅人: R5（数据密度、增广、copy-paste 通道）| 日期: 2026-09-20 | 全程 CPU，未触碰训练进程。
脚本: `analyze.py`（同目录），原始数字: `stats.json`。桶定义与 `scripts/subbucket_scores.py` 一致：**面积 px²**（<64 ≈ 边长<8px；64-256 ≈ 8-16px；256-1024 ≈ 16-32px；small=<1024px²）。

## 结论摘要（≤10 行，必须带数字）

1. 训练集小目标密度本体稀缺：69,013/1,398,374 实例是小目标（4.94%），**像素份额仅 0.124%，<64 桶只有 0.0007%**；12544 点采样下小目标前景点期望 3.9 个（均匀部分），含 importance 采样上限 ~47 点（0.37%）——小目标在 mask/dice 损失里的梯度份额量级 0.1–0.4%。
2. batch=4 每步期望可见小 GT 仅 9.5 个（名义 10.8），**<64 桶期望 0.85 个/步**，且只有 16.2% 的图含 <64 目标。
3. depth-paste bug 确证：`transforms.py:1103-1109` 只把 RGB 贴进 `image`，**从不触碰 `result["depth"]`**；`InstanceBank.deposit`（dataset.py:193-260）根本没有存深度 crop。F1 配置无 `copy_paste` 键 → 通道关闭（"堵死"= 想开不敢开，不是正在毒化 F1）。
4. 增广核算（s~U(0.5,2)+随机裁剪）：净效应≈中性——<64 桶绝对可见数 7001→5451（−22%），相对份额 0.50%→0.58%（+17%）；压碎（有效边<8px）只占小目标曝光的 9.7%。
5. 深度通道抽样 200 val 图（1126 小 GT）：掩码内 vs 邻域外归一化深度差 p50≈0.036–0.040，**仅≈1.5σ**（噪声 0.025 norm）；>2σ 的只有 27–37%。clip 0.3-0.7 饱和率 0.03%——不是 clip 抹平，是本征对比度弱+噪声。
6. paste 源池巨大：非 crowd、面积≥16 且边界完整（2px 边距）的小目标 **56,123 个**，而 bank 容量默认只有 200。
7. 收益边界：修复 depth-paste 并启用（max_paste 12-20）估计 **AP_s +2~+5pt**；不修硬开 RGB-only paste 有 −1~−3pt 风险（毒化本已 1.5σ 的弱深度 cue）。
8. 数据/增广维度合计 ≈ +3~+8pt，占缺口（0.768−0.264=0.504）的 6–16%；大头仍在架构/分数流/训练量。
9. AIM 解决了"分配"，解决不了"监督质量"：分配完美也改变不了每步 0.85 个可见 <64 GT 和 0.4% 的梯度点份额——数据维度是 AIM 的上游残余。

## 详细分析（每堵点：方法→数据→数字→根因链）

### 1. 标注统计与梯度份额（必做 1）

方法：自写游标式流式解析器（`analyze.py::stream_top_array`，ijson 不在环境、2.9GB 训练 JSON 不能整载）逐项读 images/annotations；val 结果与 EVIDENCE.md §2 锚点精确一致（3276/181684/980/1872/6679），解析器正确性有锚。

数据（train 25654 图 / 1,398,374 非 crowd 实例 / 0 crowd；val 3276 / 181,684；全部 1024×1024）：

| 量 | train | val |
|---|---|---|
| GT/图 p50/p90/max | 50 / 99 / 100 | 50 / 99 / 100 |
| small(<1024px²) 数量 / 占比 | 69,013 / 4.94% | 9,531 / 5.25% |
| 子桶 <64 / 64-256 / 256-1024 | 7,001 / 13,195 / 48,817 | 980 / 1,872 / 6,679 |
| small/图 mean / p50 / p90 / max | 2.69 / 1 / 11 / 30 | 2.91 / 1 / 12 / 26 |
| 含≥1 small 图占比 | 55.1% | 56.7% |
| 含≥1 <64 图占比 | **16.2%** | 17.6% |
| <64/图 mean（全部图） | **0.273** | 0.299 |
| small 像素份额 | **0.124%** | 0.134% |
| <64 像素份额 | **0.0007%** | 0.0008% |

- batch=4（4 GPU × ims_per_batch 1，grad_accum 1）：期望 small GT **10.76**/步（名义）；<64 桶期望 **1.09**/步。
- Dice/mask loss 点采样（K=12544，oversample_ratio 3.0，importance 0.75）：均匀部分（25%=3136 点）落在小目标前景的期望 = 3136×0.00124 ≈ **3.9 点**；即使 importance 采样把前景点占比抬到 uniform×3 的上限，小目标份额 ≤ **0.37%**（≈47 点）。分类流上 no_object_weight 0.1 + balanced_ce_min_fg_ratio 0.01 只部分补正。**小目标有效梯度份额量级 0.1–0.4%**——这就是"训练信号里小目标有效梯度份额"的直接答案。
- 根因链：单图 ~54 实例、其中 ~2.7 个小目标、中位小目标面积 479px²（≈22px 边）→ 每图小目标前景 ~1300px / 1M px → 损失采样结构性把 <64 桶（980 个 val GT、AP 0.11）压到每步不足 1 个可见样本 + 每图 0.03 的点份额。

### 2. 增广核算（必做 2）

方法：读 `ResizeScale`（transforms.py:385-465）：`scale ~ U(min,max)` 精确均匀采样；对 1024×1024 图（全部如此），target 框 1024s×1024s，`resize_scale = min(...)= s`，即每样本缩放因子恰为 s~U(0.5,2.0)。`FixedSizeCrop`：s≤1 时 pad 保留全部实例；s>1 时从 (1024s)² 画布随机裁 1024² → 点目标可见概率 1/s²（min-objects 守卫使实际略高，忽略偏保守）。闭式计算每个 GT 面积 a 的 E[可见∧落入阈值下]（`analyze.py::e_visible_below`）。

数字（train 1.4M 实例）：

| 桶 | 原始计数 | 期望可见计数 | 变化 | 原始份额 | 可见份额 |
|---|---|---|---|---|---|
| <64 | 7,001 | 5,451 | **−22%** | 0.50% | 0.58% |
| 64-256 | 13,195 | 11,104 | −16% | 0.94% | 1.19% |
| 256-1024 | 48,817 | 44,123 | −10% | 3.49% | 4.73% |
| 合计可见 | 1,398,374 | 932,249（E[vis]=2/3） | −33% | — | — |

- 压碎（小目标条件概率）：P(有效边<8px)=**9.7%**、<5.7px(面积<32)=5.8%、<4px（低于单个 stride-4 特征格）=3.4%、<2px=1.1%。
- 反向（放大救活）：90.3% 的小目标曝光保持有效边≥8px；50% 的采样放大≥1.25×。
- 每步 batch=4 可见 small **9.46**、可见 <64 **0.85**。
- 判定（净效应）：**相对增密（+17% 份额）但绝对稀释（−22% 数量），压碎 9.7%——U(0.5,2) 在该数据上近乎中性**，既不是 AP_s 的救星也不是凶手。与 EVIDENCE §5 的 c0 病理（min_scale 0.1、P(scale<0.5)=21% 压碎）对照，F1 的 0.5 已把当年最坏的增广问题修掉；继续抬 min_scale 到 0.6-0.7 只能再省 ~4pt% 的压碎曝光，边际小。
- 根因链：均匀 scale 采样对"5% 小目标"的组成只做一阶重排；s>1 的裁剪等比例丢弃所有尺寸实例（1/s²），抵消了 0.5× 把 64-256 压入 <64 的增密流入（该流入量级：64-256 桶 P(s<0.5)≈0 → 实际 <64 的期望份额增益全部来自 P(0.5<s<...) 的边缘概率重排，数值上就是 0.50%→0.58%）。

### 3. depth 通道可用性（必做 3）

方法：从含≥1 小目标的 val 图（1858/3276）中种子抽样 200 张，逐小目标解码 mask（pycocotools），深度按生产语义归一化（clip [0.3,0.7] → (d−0.3)/0.4；噪声 0.01 raw 在归一化**之前**注入 → 归一化 σ=0.025）。环域=mask 膨胀 max(2, side/2) 减 mask；另算"纯背景环"（再减该图全部其他实例 mask）以区分对比度来源。共测 1,126 个小 GT。

| 桶 | n | \|Δ\| p50 (norm) | 纯背景环 \|Δ\| p50 | SNR p50 | frac>2σ(0.05) | frac>4σ |
|---|---|---|---|---|---|---|
| <64 | 105 | 0.038 | 0.023 | 1.51 | 35.2% | 3.8% |
| 64-256 | 229 | 0.040 | 0.027 | 1.60 | 37.1% | 4.8% |
| 256-1024 | 792 | 0.036 | 0.034 | 1.46 | 27.3% | 2.5% |
| <32px²（极小群） | 59 | 0.030 | — | 1.21 | 27.1% | — |

- clip 0.3-0.7 平均饱和率 **0.03%**（原始深度 p1-p99 ≈ [0.39, 0.63]）→ **clip 没有抹平任何东西**。
- 抹平主因是本征对比度：中位小目标的内外深度差只有噪声 σ 的 1.5 倍；且纯背景环更小，说明可感知的对比度有相当部分来自"相邻零件"而非背景——在 35.6% 小目标被更大兄弟 bbox 包含的密集场景里这是双刃剑。
- 均值层面 cue 仍存在：22px 目标 ~480 前景像素，in-mask 均值噪声 SEM≈0.025/√480≈0.001，统计可分；但 <64px² 目标只有 ~64 像素且每像素 SNR 1.5——深度对最小桶是**弱可分、接近噪声本底**。
- 结论：深度通道对小目标"活着但微弱"。这直接决定堵点 1 的修复形态：paste 若不带深度，贴入实例处深度仍是背景，把 27-37% 勉强 >2σ 的样本变成 100% 的 RGB-深度矛盾样本。

### 4. depth-paste bug 精确复核（必做 4，重点）

代码事实链（experiments_archive/v317_next_stage_2026-07/source/magformer/data/）：

1. `dataset.py:645-652`：`__getitem__` 在任何 transform 之前调 `instance_bank.deposit(image, masks, boxes, labels)`——**签名里没有 depth**。
2. `dataset.py:193-260`（`_InstanceBank.deposit`）：bank 条目只含 `crop_img / crop_mask / label / area / src_h / src_w`——**没有 crop_depth 字段**。
3. `transforms.py:1103-1109`（`CopyPasteTransform.__call__` 贴入段）：
   ```python
   mask_3ch = np.stack([paste_region_mask] * 3, axis=-1)
   image[y1:y2, x1:x2] = np.where(mask_3ch, crop_img[sy1:sy2, sx1:sx2], image[y1:y2, x1:x2])
   ```
   只写 `result["image"]`；入口守卫（1009 行）只检查 masks/boxes/labels，**不检查也不处理 "depth"**。后续对 depth 的唯一操作是 `DepthNoiseAug`、`DepthNormalize`（1387-1409 行），都在 paste 之后、且不感知贴入。
4. 管线顺序（transforms.py:1311-1412）：flip → ResizeScale → FixedSizeCrop → **CopyPaste** → RGB 光度 → 深度噪声 → 深度归一化 → ToTensor。paste 时刻 depth 是 **raw 值**（未归一化）。

**机理判定：不是"贴错几何"，是"RGB 贴了、深度完全没贴"**——贴入实例处的深度仍是原背景深度。几何（y1:y2,x1:x2、sy/sx 源窗口、scale jitter）对 RGB 是自洽的，修复无需动几何。

**危害机理（若在 RGB-D 模型上启用）**：mask 监督宣称"此处是物体"，RGB 出现物体外观，深度通道却给出背景深度 → DCCG 融合（dccg_use_confidence）在训练中持续看到"RGB-物体 / 深度-背景"的矛盾对 → 要么学会对该区域降权深度（伤 27-37% >2σ 的真实深度 cue），要么把"深度不一致处=物体"学成伪相关（伤大/中目标）。在深度对比度本就 1.5σ 的数据上，这是把唯一弱模态信号系统性污染——所以该通道只能保持关闭，即"堵死"。

**现状**：`f1_full_design_256k.yaml` 无 `copy_paste` 键，schema（config/schema.py:132，`CopyPasteConfig` 默认 enabled=false）→ F1 训练未被污染；代价是 §结论摘要 7 的机会成本。另注：`copy_paste_aug.py` 是 Ghiasi 式独立 demo（仅测试引用），生产路径是 transforms.py 的 CopyPasteTransform。

### 5. 收益边界估算（必做 5）

文献量级（凭知识引用，检索当日限流未取到新链接）：
- Ghiasi et al., CVPR 2021（Simple Copy-Paste）：COCO 实例分割 +~1.2 AP（R50+LSJ）；LVIS +2.4~+3.7 AP，稀有类最大（+~6）；对 DETR 系架构一致有效；LSJ(0.5-2.0)+CP 正是 F1 同款 scale 配方。
- 小目标专用 paste 线（Kisantal et al. 2019 过采样+粘贴；SDP-CP 2022 等 AI-TOD 系）：tiny 桶 +3~+7pt。
- 单类优势：Ghiasi 的主要风险（贴入实例的类别-语境噪声）在 num_classes=1 下**不存在**——任何贴入零件都是正确正样本；且本数据单图 ~54 实例的密集语境让贴入目标不显突兀。

内部旁证：
- 密度×2-3 的量化路径：E[贴入小目标/图] = prob 0.5 × max_paste N × P(抽中小库 0.75) × 通过率(~0.65)。N=5 → 1.2/图（密度 ×1.13，不够）；**N=12-20 → 2.9-4.9/图（×2.2-×3.1）**，叠加可见基线 2.37 → 每图 5-7 个可见小目标，小目标像素份额 0.124%→0.3-0.45%，损失点份额向 1% 量级爬。
- §9 数据量旁证：同 4000 图下设计臂 vs 对照的 AP_s 相对优势 8 个窗口单调放大（+19%→+54%）、TP 分数成熟从最小桶扩散——小目标能力是"晚成型、密度/容量驱动"的量；而 c0 用全量 25654 图训 300K 步 AP_s 仍 0.236 → **图数不等于密度，密度干预才是变量**。小模型臂 4000 图上限 0.097 与 F1 全量 112K 已 0.264 的差异被容量混杂，只取方向不取数值。
- 边界（不能超过的）：AIM 裁决的 assignment headroom 仅 1.1pt（冻结模型）；E3 stride-2 oracle 天花板 0.768。密度杠杆作用于"漏检 59.2% + mask 质量 39.1%"的检测集合质量本身，与天花板正交。

**估计**：修复 depth-paste 并以 N=12-20 启用 → AP_s **+2~+5pt**（0.264 → 0.28-0.32；下界=只救 64-256/256-1024 桶的漏检，上界=<64 桶部分成型 + 过采样/SAHI 联动）。RGB-only 硬开 → **−1~−3pt**。

**总归因（必做 6）**：缺口 0.504（0.768−0.264，112K 步时点）。数据/增广维度：copy-paste(+2~5) + 小图过采样(+0.5~1.5) + SAHI crop(+1~3，未测) ≈ **+3~+8pt（缺口的 6-16%）**；其余 ~42-47pt 在架构表征（stride-2 利用率）、分数流校准、训练步数与 AIM 残余分配——与 R 系其他审阅维度衔接，不重复计入。

### AIM 覆盖度说明（数据维度 AIM 解决了什么/残余什么）

- AIM 解决：小 GT 匹配列的确定性精确 Dice（bbox+30% 窗口），把"列由噪声决定"（E2-M1）的掷硬币区清掉——**分配质量**问题。这对数据密度是前置条件：贴入的额外小目标只有先被稳定分配，其梯度才进对的 query。
- AIM 不解决（数据维度残余）：① 监督质量——每步 0.85 个可见 <64 GT、0.1-0.4% 的损失点份额不因匹配器改变（本报告核心）；② 贴入/过采样等密度供给本身（copy-paste 通道修复与调参）；③ 深度模态对小目标的弱对比度（1.5σ）与 paste 时的模态一致性；④ 增广尺度组成的中性净效应。一句话：AIM 把"分到谁"修好了，"有多少可分、每份多重"仍完全是数据维度的残余。
